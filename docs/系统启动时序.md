# 系统启动时序

本文描述当前新版硬件路线下的启动顺序。

## 一句话原则

先保证安全，再点亮表情，最后启动网络和业务。

## 启动顺序

```text
上电
  -> SystemBootstrap.boot()
  -> App.begin()
  -> 串口日志
  -> HardwareManager.begin()
       -> 电池和充电状态
       -> I2C 和 OLED
       -> WS2812
       -> 电机驱动
       -> 雷达
       -> 麦克风输入
       -> 音频输出
       -> 硬件自检服务
  -> 时间服务
  -> 提醒存储
  -> MCP
  -> 网页配置服务
  -> 开机剧情
```

## 安全要求

- 电机默认停止。
- 灯默认低亮或关闭。
- 音频输出默认不播放。
- 没有拿到时间前，不触发真实提醒。
- 雷达未就绪时，不影响本地提醒。

## 当前启动编排状态

- `main.cpp` 只创建 `SystemBootstrap`，并调用 `boot()` / `run()`。
- `HardwareManager` 负责硬件初始化顺序。
- `/api/status` 会返回 `systemMode`、硬件降级状态和当前保留能力。
- 配网模式仍由 `WebConfigServer` 根据 WiFi 配置决定。
- 当前降级判断先覆盖 OLED、WS2812、麦克风输入和喇叭输出。

## 音频启动

当前代码里 `AudioOutput` 已经作为 NS4168 的基础输出层。

启动时：

1. 初始化 I2S 输出。
2. 配置 `SPK_BCK / SPK_LCK / SPK_DOUT`。
3. 默认不自动播放，避免上电突然出声。
4. 需要实物验证时，通过 `playTestTone()` 播放短测试音。
5. 确认 NS4168 有声音且没有明显爆音。

## 麦克风启动

当前代码里 `AudioInput` 已经作为 INMP441 的基础输入层。

1. 初始化 I2S 输入。
2. 配置 `I2S_BCLK / I2S_LRCLK / I2S_DIN`。
3. 读取一小段原始音频。
4. 每秒打印一次音量诊断。
5. 实物回来后根据串口日志确认麦克风是否有输入。

## 提醒启动

- 存储先启动。
- 时间服务再启动。
- 时间未准备好时，只允许读写提醒，不允许判断到期。
- 时间准备好后，`ReminderManager` 才开始计算到期事件。

## 降级规则

| 模块 | 失败后怎么做 |
| --- | --- |
| OLED | 保留提醒和网页服务，串口提示 |
| WS2812 | 保留提醒和网页服务，串口提示 |
| 电机 | 禁用动作，只保留表情和声音 |
| 雷达 | 禁用存在感知，只保留提醒 |
| 麦克风输入 | 禁用语音入口，保留网页、MCP 和本地提醒 |
| 音频输出 | 禁用声音，只保留表情、灯光、动作 |
| 时间服务 | 暂停到期判断，允许网页同步时间 |
| 网页服务 | 保留本地提醒和串口日志 |

当前代码中的最小降级能力：

| 能力 | 规则 |
| --- | --- |
| 提醒 | 默认保留 |
| 网页 | 默认保留 |
| 视觉反馈 | OLED 或 WS2812 任一可用就保留 |
| 声音输出 | 喇叭 I2S 初始化成功才可用 |
| 语音输入 | 麦克风 I2S 初始化成功才可用 |

## 开机剧情

开机剧情必须短：

- 表情从睡眼到醒来。
- 灯光暖色低亮。
- 电机轻微动一下。
- 台词不宜太长。

目的不是炫技，而是告诉用户：铜豆醒了。
