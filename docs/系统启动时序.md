# 系统启动时序

本文描述当前新版硬件路线下的启动顺序。

## 一句话原则

先保证安全，再点亮表情，最后启动网络和业务。

## 启动顺序

```text
上电
  -> 串口日志
  -> 电池和充电状态
  -> I2C 和 OLED
  -> WS2812
  -> 电机驱动
  -> 雷达
  -> 音频输出占位
  -> 时间服务
  -> 提醒存储
  -> MCP
  -> 网页配置服务
  -> 开机剧情
```

## 安全要求

- 电机默认停止。
- 灯默认低亮或关闭。
- 音频输出默认不播放。
- 没有拿到时间前，不触发真实提醒。
- 雷达未就绪时，不影响本地提醒。

## 音频启动

当前代码里 `AudioOutput` 先作为占位层。

后续接入真实音频时：

1. 初始化 I2S 输出。
2. 配置 `SPK_BCK / SPK_LCK / SPK_DOUT`。
3. 播放短测试音。
4. 确认 NS4168 有声音且没有明显爆音。

## 麦克风启动

后续接入单麦时：

1. 初始化 I2S 输入。
2. 配置 `I2S_BCLK / I2S_LRCLK / I2S_DIN`。
3. 读取一小段原始音频。
4. 打印音量均方根值。
5. 保存测试音频或通过串口输出诊断数据。

## 提醒启动

- 存储先启动。
- 时间服务再启动。
- 时间未准备好时，只允许读写提醒，不允许判断到期。
- 时间准备好后，`ReminderManager` 才开始计算到期事件。

## 降级规则

| 模块 | 失败后怎么做 |
| --- | --- |
| OLED | 保留提醒和网页服务，串口提示 |
| WS2812 | 保留提醒和网页服务，串口提示 |
| 电机 | 禁用动作，只保留表情和声音 |
| 雷达 | 禁用存在感知，只保留提醒 |
| 音频输出 | 禁用声音，只保留表情、灯光、动作 |
| 时间服务 | 暂停到期判断，允许网页同步时间 |
| 网页服务 | 保留本地提醒和串口日志 |

## 开机剧情

开机剧情必须短：

- 表情从睡眼到醒来。
- 灯光暖色低亮。
- 电机轻微动一下。
- 台词不宜太长。

目的不是炫技，而是告诉用户：铜豆醒了。
