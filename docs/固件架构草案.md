# 固件架构草案

本文描述当前新版硬件路线下的固件骨架。

## 目标

第一版固件要先做到：

- 能启动。
- 能显示表情。
- 能控制灯。
- 能控制双电机。
- 能检测电池和充电状态。
- 能初始化 INMP441 单麦，并输出音量诊断日志。
- 能保存提醒并触发剧情。
- 能通过网页配置基础数据。
- 能初始化 NS4168 I2S 输出，并提供短测试音。

## 当前分层

```text
App
  -> Hardware
  -> Time / Reminder
  -> Scenario
  -> Web
  -> MCP
```

## 硬件层

硬件层只管硬件，不懂剧情。

- `AudioInput`：INMP441 麦克风输入，提供采样和音量诊断。
- `AudioOutput`：NS4168 I2S 输出，提供短测试音。
- `BatteryMonitor`：读取 USB、电池、充电、充满状态。
- `DisplayBus`：初始化 I2C。
- `FaceDisplay`：显示 OLED 表情。
- `LedPixel`：控制 WS2812。
- `MotorDriver`：控制 AT8833。
- `RadarSensor`：读取雷达信号。

## 剧情层

剧情层负责把事件变成“表情、灯光、动作、台词”的组合。

- `ScenarioEngine`：选择剧情计划。
- `ScenarioExecutor`：非阻塞执行剧情计划。
- `ScenarioLibrary`：内置剧情包。
- `VoiceLinePack`：台词表。

## 提醒层

- `TimeService`：提供当前时间。
- `ReminderStore`：保存提醒。
- `ReminderManager`：判断提醒是否到期，并发出事件。

## 网页层

- `WebConfigServer`：提供配网、时间同步、提醒和剧情配置接口。
- `ScenarioConfigApi`：剧情配置接口。
- `ScenarioConfigStore`：保存用户剧情配置。

## MCP 层

当前先保留小而完整的工具层：

- 获取状态
- 创建提醒
- 查询提醒
- 删除提醒

后续接电脑端大模型时再扩展。

## 下一步

1. 用实物验证 `INMP441` 单麦采音。
2. 用实物验证 `NS4168` I2S 测试音。
3. 把 `AudioOutput` 从测试音升级成真实语音播放。
4. 用 JiShi 的系统编排和网页配置能力替换当前简化骨架。
