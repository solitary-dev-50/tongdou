# 网络信息查询

## 功能和边界

用户可以自然询问铜豆自己的网络地址或本机控制台入口，例如：

- “你的地址是多少？”
- “我怎么进入你的控制台？”
- “铜豆，我怎么找到你？”
- “告诉我你的网络地址。”
- “手机上怎么打开你的设置页面？”

这些是验收示例，不是固定口令。现有服务器大模型根据工具说明理解用户意思，固件不增加关键词匹配或本地语义判断。

工具名为 `tongdou.network.show_info`，无需参数。它查询的是铜豆本机的网页入口，不是现实住址，也不是服务器管理后台。

中文成功确认示例：“我的地址已经显示在屏幕上了，照着找我就行。”服务器根据设备真实执行结果，沿用当前对话语言和铜豆人格组织短回复，并通过原有语音合成、播放流程播报。默认不逐位念地址。

## 现有链路与最小切入点

```text
原有唤醒或连续对话入口
  → 麦克风采音和上传
  → 服务器语音识别
  → 服务器意图理解或大模型工具调用
  → 通过原有语音长连接调用设备工具
  → McpServer → AppCommandService → NetworkInfoService
  → 读取设备当前地址、显示地址页、返回实际结果
  → 服务器组织短回复并合成语音
  → 原有播放、连续对话和退出流程
```

已检查平级 `tongdou-server` 中的 `receiveAudioHandle.py`、`intentHandler.py`、`connection.py` 和 `core/providers/tools/device_mcp/`：服务器在连接初始化后通过 `tools/list` 自动读取设备工具说明，加入当前工具集合，执行后将结果交回大模型。此次无需修改服务器或另外安装插件；固件更新并重新连接后，服务器重新发现新增工具。服务器需要启用现有工具调用能力。

最小切入点是已有语音工具白名单。新增一个工具即可复用自然语言理解和播报，采音、识别、上传、声音播放、连续对话、正常退出的时序代码均不修改。

## 设备执行逻辑

1. 每次调用都从无线网络驱动读取当前地址，优先使用已连接网络的本机地址。
2. 未取得正常网络地址时，仅在设备配网热点确实开启且有地址时，返回真实热点地址。两者都不可用则返回 `network_unavailable`，不显示 `0.0.0.0` 或旧地址。
3. 用当前地址组成 `http://地址/`，本机网页服务仍使用原有 80 端口和根路径。
   正式固件连接无线网络后同时注册固定的 `http://tongdou.local/` mDNS 别名；浏览器或局域网不支持 mDNS 时继续使用屏幕上的 IP 地址。
4. 到点提醒正在播报时返回 `reminder_busy`；屏幕不可用时返回 `display_unavailable`。工具结果中只有 `displayed=true` 才允许宣称已经显示。
5. 通过已有 `FaceDisplay::showBitmap128x48` 显示三行内容：控制台与 `http://`、完整地址、浏览器打开提示。
6. 地址页保留至少 30 秒；等待语音回复或正在播报时继续保留，说完后再给足 30 秒阅读时间。自动进入下一轮监听不收起；服务端真正识别到用户下一句 `stt` 文本后立即收起并恢复正常表情。重复查询重新计时。地址变化或断网时收起旧地址页；提醒或其他明确屏幕内容接管时立即让出，不抢回屏幕。
7. 普通语音视觉反馈只暂时让出屏幕，灯光仍按“听、想、说”运行。地址页结束后恢复原有表情逻辑。

正常中文界面为“控制台 http://”“当前实际地址”“同网浏览器打开”；配网热点界面最后一行改为“先连配网热点”。设备当前语言为中文时显示中文提示，其他语言暂用简短英文提示，语音仍由服务器按当前语言回复。

固定小字只占 2048 字节位图，不加入完整字库、语音文件、配置项或新交互。地址使用独立数字小字模，最长 15 字符占 103 像素，能完整放入 128 像素宽屏幕。字图由 `firmware/tools/build_network_info_labels.py --font <支持中英文的字体文件>` 生成；当前使用服务器已有的 `main/manager-web/public/generator/static/fonts/noto_qwen.ttf`，普通固件编译不依赖这个字体或生成脚本。

## 验证

电脑端执行：

```powershell
python firmware/tools/test_network_info.py
cd firmware
platformio run
```

电脑端测试编译真实 `NetworkInfoService.cpp` 和 `VoiceVisualFeedback.cpp`，仅替换硬件依赖。覆盖无地址、正常地址、重复查询、地址改变、断网、配网热点、屏幕失败、提醒优先、语音听想说状态、空闲收尾和毫秒计数回绕。可传 `--preview <输出图片路径>` 导出真实显示缓冲检查排版。

实机验收清单：

1. 更新固件并重新连接服务器，确认发现 `tongdou.network.show_info`，语音工具总数为七个。
2. 依次说上面的五种自然表达。确认每次均实际调用工具，显示本机地址及浏览器提示，然后简短语音确认。
3. 手机与铜豆连接同一无线网络，在浏览器打开屏幕地址，确认进入铜豆本机控制台。
4. 接着问普通问题、当前音量，再创建一条提醒，确认连续对话和原有工具正常；自动进入监听时地址页仍在，服务端识别到普通问题文本后地址页立即收起；服务器慢回复时，地址保留到说完后至少 30 秒。
5. 地址显示期间让已有提醒到点，确认提醒照常显示、播报。重复查询、换网重连后再查询，确认地址实时更新。
6. 询问“你的现实住址在哪”“怎么进入服务器管理后台”，确认不会把本机地址当作这些问题的答案。
7. 断网时自然语音仍受原有在线识别链路限制；没有新增离线意图识别。配网热点和屏幕失败可通过本地 `/api/mcp` 调试或电脑端模拟验证。

本地工具调用示例，向设备现有 `/api/mcp` 发送：

```json
{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"tongdou.network.show_info","arguments":{}}}
```

本地接口用于验证设备查询和显示，不会自行启动语音播报；语音确认属于现有服务器工具回复链路。
