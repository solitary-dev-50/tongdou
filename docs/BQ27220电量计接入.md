# BQ27220 电量计接入

适用正式主板 V9.4。V9.0 保留原硬件与独立升级型号，不探测电量计，不占用新中断脚。本次完成代码接入、电脑模拟测试和正式固件编译，尚未连接 V9.4 实机验收。

## 硬件与文件职责

| 项目 | 定义 |
| --- | --- |
| 电量计 | BQ27220YZFR，7 位地址 `0x55` |
| 数据线、时钟线 | IO6、IO7，共用原有两线通信总线 |
| GPOUT 状态通知 | IO34，输入、下降沿中断；外部 10kΩ 上拉到 3.3V |
| QMI8658 中断一、中断二 | IO33、IO47；保留现有姿态轮询业务 |
| 备用电压检测 | IO8，原有 100kΩ / 100kΩ 分压 |

| 电流采样电阻 | 10mΩ，保留芯片默认校准，不额外乘比例 |

## 启动和运行参数

每次启动及故障重试前，主机暂停 IO34 中断，以开漏方式将 GPOUT 拉低至少 2 毫秒，然后恢复输入，让外部 10kΩ 电阻产生上升沿，尝试退出芯片关机状态。释放后等待 300 毫秒才访问总线；所有等待均分步执行，不主动输出高电平。串口 `wake gpout low pulse sent` 只表示已执行主机唤醒动作，是否成功仍以芯片响应为准。

启动先使用备用电压。电量计在主循环分步执行设备识别（设备号 `0x0220`）、解除保护、检查运行参数、按需进入配置状态、写入并读回核对、退出配置、恢复保护、确认电池在位及初始化完成。最后完整读取一帧有效数据才切为电量计来源。各等待阶段由时间戳推进，没有 `delay()` 或等待芯片的忙循环。

只修改下表的可擦除运行内存（RAM），不发送一次性烧录（OTP）命令，不修改电流增益或校准。已有参数相同时跳过写入。容量迁移时先写满充容量、最后写设计容量；普通重连保留已经学习得到的满充容量。

| 运行地址 | 项目 | 写入规则 |
| --- | --- | --- |
| `0x929D` | 初始满充容量 | 仅设计容量不符时设置为 1200mAh |
| `0x9206` | 工作配置 A | 内部温度、主机声明电池在位，关闭 BAT_GD 输出，其余位保留 |
| `0x9208` | 工作配置 B | 低电量及充放电变化通知开启，`INT_POL=0` 低有效 |
| `0x920D` | 引脚配置 | 关闭独占 GPOUT 的电池容量跳变专用模式 |
| `0x920B` | 百分比变化通知 | 1% |
| `0x91FD` | 计量模型的充电电压 | 4200mV；不改变 TP4057 实际充电电压 |
| `0x9221` | 深度休眠电流门限 | 按官方要求关闭，写 0 |
| `0x929F` | 设计容量 | 1200mAh |

地址采用低字节在前，运行参数采用高字节在前；校验和与长度合并写入 `0x60`，每项写完都重新选址并核对。进入/退出配置至少等 2 秒，状态等待设有超时。使用标准出厂访问密钥；芯片若已改过密钥，初始化会报访问失败并保留备用电压。

## 定时读取与中断

每秒开始一帧，分多次更新读取电压、实时电流、平均电流、剩余百分比、剩余容量、满充容量、温度和健康度。额外检查工作状态与设计容量，发现电量计复位或配置丢失时重新初始化。电流按有符号毫安提供，充电为正、放电为负；温度从 0.1K 转成摄氏度。

IO34 的中断处理只累计次数，不打印日志、不访问总线。主循环收到通知后安排读取，两帧开始至少相隔 500 毫秒，避免超过每秒两帧。结合状态位和百分比变化记录低电量、百分比变化事件；软件低电量门限为 10%。没有新增关机、电机停止或剧情策略。

驱动复用原 `Wire` 对象，不重新初始化总线、不改变时钟。每次更新最多进行一次短读写；底层仍是同步传输，每次总线调用使用 10 毫秒超时并恢复原值，不能理解为总线占用为零。音频和运动在总线故障时是否仍满足实时要求，需要实机同时运行验证。

## 备用切换与数据接口

原 ADC（主控模拟电压检测）每 500 毫秒采样，保留原始值并提供分压换算后的毫伏值。USB、充电、充满状态继续读取原引脚。

- 初始状态、访问失败、读回不符、数据不完整或异常：使用 ADC 电压。
- 完整数据超过 5 秒未更新：缓存失效，使用 ADC 电压。
- 发生通信/初始化故障：立即标记失效，尽力退出配置并恢复保护，约 30 秒后重试；初始化及完整读取恢复才重新切换。
- 备用状态只提供电压，不根据电压猜百分比；电量计独有数据在网页接口返回 `null`，诊断输出“不可用”。

`GET /api/status` 的 `battery` 对象保留 `usb`、`charging`、`standby`、`rawAdc`，新增：

语音和其他设备侧调用统一使用 MCP 工具 `tongdou.battery.get_status`，它读取同一个 `BatteryMonitor::read()` 快照，不主动触发额外 I²C 读取。这样语音、电池状态栏、网页和诊断不会各自维护一套电量判断。

| 字段 | 含义 |
| --- | --- |
| `source`、`gaugeValid`、`gaugeError` | 当前来源 `bq27220` / `adc`、有效性、故障原因 |
| `voltageMv`、`adcVoltageMv` | 当前选用电压、备用电压，毫伏 |
| `currentMa`、`averageCurrentMa` | 实时、平均电流，毫安 |
| `stateOfChargePercent` | 剩余电量百分比 |
| `remainingCapacityMah`、`fullChargeCapacityMah` | 剩余、满充容量，毫安时 |
| `temperatureC`、`temperatureSource` | 摄氏温度，来源 `internal_sensor` 表示芯片内部温度 |
| `stateOfHealthPercent` | 电池健康度百分比 |
| `lowBattery`、`gaugeSleeping`、`sampledAtMs` | 低电量、休眠状态、采样时间 |
| `gpoutInterruptCount`、`socChangeCount`、`lowBatteryEventCount` | 中断、百分比变化、低电量事件次数 |

串口启动打印地址、引脚、容量和只写运行内存的说明；初始化成功、来源切换和故障即时打印；正常读数每 30 秒或状态变化时打印。网页和诊断读取缓存，不额外轮询芯片。

## 验证与实机清单

电脑验证命令：

```powershell
python firmware/tools/test_bq27220.py
cd firmware
platformio run -e esp32s3 -e esp32s3_v94
```

两种正式应用均编译通过。模拟测试覆盖八项数据、正负电流、RAM 校验和与读回、初始化失败、错误设备、拒绝解封、断线及短读回退、重连保留学习容量、电量计掉电配置丢失、数据过期、中断限频、毫秒计数回绕。V9.0 测试确认无电量计事务、无新中断占用。模拟总线验证软件逻辑，不能代替芯片通信验收。

待上板逐项执行：

1. 烧入 V9.4 正式固件，确认扫描到 `0x55`，串口出现 `init/readback ok`，来源变为 `bq27220`；主控重启及电池断电重启均能恢复。
2. 用万用表和已知负载核对电压、电流数值及充放电符号，对照充电/充满状态；不修改默认电流比例掩盖接线问题。
3. 用逻辑分析仪观察 IO34 空闲高电平、通知低脉冲，确认电量变化/低电量时中断计数增长；检查 IO33、IO47 未被其他功能驱动。
4. 同时进行语音采集和播放、电机动作、姿态读取、OLED 刷新，观察卡顿、总线错误和看门狗复位，特别检查总线断线时的影响。
5. 在受控条件下中断电量计通信，确认电压切到 ADC，百分比/电流显示不可用；恢复后等待重试，确认自动回到电量计。
6. 完成一次受控充放电循环，核对满充、低电量、剩余容量与健康度。1200mAh 和 4.2V 不能确定电芯放电曲线；准确计量仍需匹配实际电芯的 CEDV 参数（按负载和温度补偿放电终点的参数）。目前保留其他模型参数，不能承诺百分比和健康度已校准。
7. 当前读的是芯片内部温度，不能当成直接贴在电池上的温度探头。若后续明确采用外部热敏电阻，需按实际接线单独配置。
8. V9.0 验证原电压、充电和姿态功能；两种主板各自检查升级型号，不能互刷。升级与救援验证见 [远程固件升级](远程固件升级.md)。
