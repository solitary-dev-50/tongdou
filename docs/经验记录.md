# 经验记录

本文只记录当前硬件路线下仍然有效的经验。

## 1. 当前硬件路线必须统一

现象：

- 项目已经切到 `ESP32-S3 + PDM 单麦 + NS4168` 路线。
- V9 PCB 新增 `QMI8658A`、`IO4` Logo 触摸，并将 `AT8833CT nFAULT` 故障输出接入 `IO37`。
- 所有硬件、固件、文档都必须围绕这条路线写。

结论：

- 主控直接负责采音、联网、播放和外设控制。
- 麦克风使用 `IM72D128V01XTMA1` PDM 数字麦克风。
- 功放使用 `NS4168` I2S 数字功放。
- `QMI8658A` 与 OLED 共用 `IO5/IO6` I2C 总线。
- Logo 触摸接 `IO4`，不再把 `IO4` 写成麦克风预留脚。
- 后续不再维护已经砍掉的旧音频处理链路。

怎么验证：

- 搜索主线文档和固件，不应再出现已经砍掉的外部音频处理芯片路线。
- 搜索主线文档，不应再把 `IO4` 写成当前未使用的麦克风预留脚。

## 1.1 V9 新硬件先诊断，后接剧情

现象：

- V9 新增 Logo 触摸、`QMI8658A` 和 `MOTOR_FAULT / IO37`。
- 这两个能力都容易受电机、喇叭、供电和机身结构影响。

结论：

- 第一阶段只做串口或网页诊断。
- 触摸先看原始值、基线和误触。
- `QMI8658A` 先看 I2C 扫描、芯片身份和原始姿态数据。
- 数据稳定后，再接摸摸头、拿起、敲击和倾倒等互动。

怎么验证：

- 按 `docs/V9_PCB回板验证清单.md` 逐项测。
- 电机动作和喇叭播放时，触摸不能明显误触。
- 电机短动作前后，`MOTOR_FAULT / IO37` 应保持高电平；一旦低电平，先停电机再排查电机线、驱动和供电。
- OLED 刷新时，`QMI8658A` 读取不能影响显示。

## 1.2 QMI8658A 直行纠偏到此为止

现象：

- V9 样机的 `QMI8658A` 已能被识别，实测地址为 `0x6A`，芯片身份读数为 `0x05`。
- 手动左右转测试确认偏航主要在 `Z` 轴。
- `/motor` 页面用陀螺仪自动直行时，肉眼已经基本直行。
- 停止时主动急刹会让单侧轮子显得更突兀。

结论：

- 铜豆水平放置时，偏航轴按 `Z` 轴处理；PCB 顶层朝下只影响符号，不直接改成 `X/Y`。
- 自动直行不要再靠固定左右轮补偿硬顶，而是从左右同速起步，用角速度和累积偏航小步修正。
- 收尾用软停，不用主动急刹。
- 这部分先作为演示固件 `/motor` 的空载检测能力，不接剧情、不接提醒确认、不做随机互动。

怎么验证：

- 打开 `http://192.168.4.1/motor`。
- 点击 `GYRO AUTO STRAIGHT`。
- 串口应看到 `bias_term=0`、`stage=first_drive` 左右同速、运行中 `correction` 可正可负、结束出现 `stage=soft_stop`。
- 肉眼观察基本直行即可，不继续追求毫米级直线。

## 1.3 Logo 触摸与陀螺仪动作回正

现象：

- V9 样机的 `LOGO_TOUCH / IO4` 已完成最小交互验证。
- 单击 Logo 可触发眨眼。
- 双击 Logo 可触发左右扭动。
- 长按 Logo 可在休眠和唤醒之间切换。

结论：

- Logo 触摸输入可用，后续可以作为明确主动输入。
- 需要回到原位的动作，不应只靠固定动作时长判断是否回正。
- 这类动作应优先使用 `QMI8658A` 的 `Z` 轴偏航数据做回正。
- 当前演示固件的 Logo 双击扭动已经接入陀螺仪回正，可作为后续动作迁移模板。

怎么验证：

- 双击 Logo。
- 串口应看到 `logo action=double_tap_gyro_wiggle`。
- 串口应看到 `gyro wiggle return begin` 和 `gyro wiggle done`。
- 肉眼观察扭动后能回到接近原来的朝向。

## 2. NS4168 先保持 5V 供电

现象：

- 当前原理图中 `NS4168` 接开关后的 `+5V`。
- `ESP32-S3` 输出 I2S 信号是 3.3V。

结论：

- 这一版先不改原理图。
- 打样回来后必须实测 `NS4168` 是否稳定识别 3.3V I2S 信号。

怎么验证：

- 播放固定测试音。
- 用逻辑分析仪看 `BCLK / LRCLK / SDATA`。
- 听是否有断音、杂音、完全无声。

## 3. PDM 麦克风必须注意声孔

现象：

- `IM72D128V01XTMA1` 是底部进音。
- 原理图接对不代表 PCB 就能收音。

结论：

- PCB 封装必须有声孔。
- 声孔不能被外壳、铜皮、阻焊或丝印挡住。
- 麦克风要远离电机、功放、升压电感。

怎么验证：

- 目检 PCB 封装和外壳开孔。
- 上电后录制一段原始音频，看波形和噪声。

## 4. 剧情资产不是白做

现象：

- 硬件路线切换后，旧输入输出链路被清理。
- 但铜豆的剧情、表情、灯效、动作和台词仍然是核心资产。

结论：

- 剧情包继续保留。
- 表情、灯光、动作模块继续保留。
- 播放层从旧接口切到 `AudioOutput`，后续接 `NS4168`。

怎么验证：

- 运行剧情模拟器。
- 固件编译通过。
- 串口能打印剧情计划和音频台词。

## 5. 文档要保持当前事实

现象：

- 旧路线资料容易把后续开发带偏。

结论：

- 没用的旧资料直接删除。
- 主线文档只写当前硬件和当前固件方向。
- 如果某个旧结论已经不适用，不要留在经验记录里。

怎么验证：

- 全项目搜索旧关键词。
- 搜索结果只允许出现在 `.git` 历史里。

## 6. 不要硬切不稳定的 Arduino ESP32 3.x 平台

现象：
- JiShi 最新音频代码使用 `driver/i2s_std.h`。
- 铜豆当前官方稳定平台 `platformio/espressif32@6.10.0` 不包含这个头文件。
- 尝试切到 `pioarduino/platform-espressif32` 后，虽然能找到新版 I2S 头文件，但 Windows 下会遇到编译器入口、C++ 标准库、`newlib`/`picolibc` 头文件不匹配等问题。

结论：
- 目前不要把铜豆主线强行切到 `pioarduino/platform-espressif32`。
- `firmware/platformio.ini` 先固定为 `platformio/espressif32@6.10.0`，保证可编译。
- `AudioInput` 和 `AudioOutput` 暂时保留当前稳定 I2S 驱动写法。

怎么验证：
- 执行 `cd firmware && platformio run`。
- 只有编译通过，才允许继续迁移下一步。
