# 演示版固件实施文档

这份文档只负责一件事：

> 把铜豆众筹视频用的演示版固件做清楚。

它不是正式固件完整需求，也不是网页配置系统说明。  
大白话说：正式固件负责长期生活，演示版固件负责让铜豆在镜头前稳定、好控、像活的。

---

## 1. 一句话结论

演示版固件采用：

> **铜豆自建无线热点 + 手机浏览器数字按钮页面 + 1 到 7 场景触发 + 非阻塞剧情播放器。**

手机只是拍摄时的遥控器。  
铜豆在画面里表现为一个独立工作的桌面搭子，不需要露出电脑连接线，也不需要展示复杂后台。

---

## 2. 演示目标

这版固件优先服务短视频和众筹页面。

必须做到：

- 一打开电源，铜豆能进入待机状态。
- 手机连上铜豆热点后，可以打开演示页面。
- 页面只显示大号数字按钮。
- 点 `1` 到 `7`，铜豆播放对应演示剧情。
- 点 `0`，铜豆停止当前剧情并回到待机。
- 每个剧情都按固定时间轴执行屏幕、灯光、电机和声音。
- 每次触发同一个按钮，表现尽量一致，方便反复拍摄。

明确不做：

- 不做开空调施法。
- 不做智能音箱路线。
- 不做全天候唤醒和闲聊。
- 不用预录摘要冒充大模型回答。
- 不让网页直接控制灯、电机、屏幕的底层细节。

---

## 3. 视频结构

视频采用 `AIDA` 模型。  
这里的 `AIDA` 是经典营销结构：

- `Attention`：吸引注意力。
- `Interest`：激发兴趣。
- `Desire`：勾起欲望。
- `Action`：促成行动。

| 视频段落 | 时间 | 演示按钮 | 画面作用 |
| --- | --- | --- | --- |
| 黄金开头 | 0 到 8 秒 | `1`、`2` | 用深夜加班嘴欠提醒抓住注意力 |
| 情绪过渡 | 8 到 18 秒 | `3` | 展示清晨唤醒和温柔一面 |
| 核心卖点 | 18 到 38 秒 | `4`、`5` | 展示邮件摘要和不打扰工作流 |
| 视觉高潮 | 38 到 48 秒 | `6` | 展示嘴硬小舞步、电机和黄铜结构质感 |
| 信任收尾 | 48 到 58 秒 | 拍实物和控制台 | 展示黄铜件、焊接、治具、网页控制 |
| 行动召唤 | 58 到 60 秒 | `7` | 用财迷眼和台词收口 |

## 4. 控制方式

### 4.1 固件启动后

铜豆启动后创建无线热点：

```txt
TongDou-Demo
```

手机连接这个热点后，浏览器打开：

```txt
http://192.168.4.1/demo
```

如果后续希望更省事，可以让根路径 `/` 自动跳转到 `/demo`。

### 4.2 演示页面

页面只需要大按钮：

```txt
1  2  3  4
5  6  7  0
```

页面显示内容：

- 当前连接状态。
- 当前播放场景编号。
- `1` 到 `7` 场景按钮。
- `0` 停止按钮。

页面不要做复杂配置。  
这个页面是拍摄遥控器，不是正式用户后台。

### 4.3 按钮映射

| 按钮 | 场景编号 | 场景名称 | 用途 |
| --- | --- | --- | --- |
| `1` | `night_gossip_hook` | 深夜加班吃瓜开头 | 视频开场抓人 |
| `2` | `night_coward_tail` | 深夜提醒装怂收尾 | 反差萌，避免只贱不软 |
| `3` | `morning_wakeup` | 清晨开机唤醒 | 治愈过渡 |
| `4` | `email_silent_notice` | 邮件信封静默提醒 | 展示不打扰 |
| `5` | `realtime_email_summary` | 实时语音邮件摘要 | 展示实用价值 |
| `6` | `cheeky_dance` | 嘴硬小舞步 | 动作高潮 |
| `7` | `crowdfunding_call` | 众筹财迷收尾 | 促成支持 |
| `0` | `idle_stop` | 停止并回待机 | 拍摄控场 |

## 5. 网页接口

演示版接口独立于正式网页配置接口。

建议接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/demo` | 返回演示控制页面 |
| `POST` | `/api/demo/scene` | 触发某个演示场景 |
| `GET` | `/api/demo/status` | 查询当前演示状态 |

`POST /api/demo/scene` 请求体：

```json
{
  "id": 1
}
```

返回：

```json
{
  "ok": true,
  "scene": "night_gossip_hook",
  "playing": true
}
```

说明：

- 按钮 `5` 触发实时语音，不再通过接口写入固定摘要。
- 邮件、日程、电脑任务这类外部内容，由电脑端小智服务端或后续 `MCP` 工具整理。
- `MCP` 是模型上下文协议，大白话就是让电脑端助手能调用工具、把结果交给铜豆。

## 6. 固件模块设计

演示版固件可以新增 `firmware/src/demo` 目录。

### 6.1 文件职责

| 文件 | 只负责什么 |
| --- | --- |
| `DemoSceneId.h` | 定义演示场景编号和名称 |
| `DemoSceneTypes.h` | 定义演示时间轴的数据结构 |
| `DemoSceneLibrary.h/.cpp` | 保存 1 到 7 的固定演示剧情 |
| `DemoScenePlayer.h/.cpp` | 按时间轴非阻塞播放剧情 |
| `DemoWebPage.h/.cpp` | 提供演示页面和演示接口 |

单一职责要求：

- `DemoWebPage` 只接收按钮请求，不直接控制硬件。
- `DemoSceneLibrary` 只保存剧情数据，不负责播放。
- `DemoScenePlayer` 只按时间播放，不解析网页请求。
- 硬件层仍然只管硬件，不知道“众筹收尾”“吃瓜开头”是什么。

### 6.2 依赖关系

推荐关系：

```txt
WebConfigServer
  -> DemoWebPage
    -> DemoScenePlayer
      -> ScenarioExecutor
        -> FaceDisplay / LedPixel / MotorDriver / AudioOutput
```

大白话说：

- 网页负责按按钮。
- 演示页负责把按钮变成场景编号。
- 剧情播放器负责按时间喊动作。
- 正式剧情执行器负责把动作交给屏幕、灯、电机和声音。

这样做的好处是：  
演示版不会绕过现有剧情执行层，以后可以把有价值的演示剧情平滑搬进正式剧情包。

## 7. 时间轴数据结构

每个场景是一组步骤。

建议结构：

```cpp
struct DemoSceneStep {
  uint16_t atMs;
  FaceAction face;
  LightAction light;
  MotionAction motion;
  VoiceLine voice;
  uint16_t durationMs;
};
```

字段解释：

| 字段 | 含义 |
| --- | --- |
| `atMs` | 从场景开始算，第几毫秒执行 |
| `face` | 屏幕表情动作 |
| `light` | 灯光动作 |
| `motion` | 电机动作 |
| `voice` | 台词或声音 |
| `durationMs` | 本步建议持续时间 |

执行规则：

- `DemoScenePlayer` 每轮 `update()` 检查时间。
- 到点后，把当前步骤转成 `ScenarioPlan`。
- 调用 `ScenarioExecutor.execute(plan)`。
- 播放期间不使用 `delay()`。
- 新场景触发时，可以中断旧场景并从新场景第一步开始。
- `0` 必须立刻停止动作、熄灭或回待机。

## 8. 场景详细设计

### 8.1 按钮 1：深夜加班吃瓜开头

用途：

> 视频前 3 秒抓住用户。

画面：

- 深夜工位。
- 屏幕偏暗。
- 铜豆突然眯眼。
- 身体微微前探。
- 暖光低亮。

台词国内版：

> “几点了还不回家？要跪搓衣板咯，我有瓜吃了，哈哈哈……”

台词海外版：

> “Still working? Careful, the couch is waiting. I brought popcorn.”

> “还在干活？小心今晚只能睡沙发。我瓜子都准备好了。”

| 时间 | 表情 | 灯光 | 动作 | 声音 |
| --- | --- | --- | --- | --- |
| 0 毫秒 | `Squint` | `DimWarm` | `None` | `None` |
| 300 毫秒 | `Squint` | `DimWarm` | `LeanForward` | `None` |
| 700 毫秒 | `Fierce` | `DimWarm` | `None` | `DemoNightGossip` |
| 3600 毫秒 | `Proud` | `WeakBreath` | `None` | `None` |

### 8.5 按钮 5：实时语音邮件摘要

用途：

> 展示铜豆不是玩具，它能听用户说话，把问题交给电脑端小智服务端，再把回答从自己嘴里说出来。

拍摄动作：

操盘手在镜头外点 `5`。  
铜豆进入聆听状态，用户问：

> “刚才什么邮件？”

铜豆把真实麦克风音频发给小智服务端。  
服务端识别后生成回答，铜豆播出，例如：

> “刚才有一封供应商邮件，主要是确认黄铜件打样时间。”

时间轴：

| 时间 | 表情 | 灯光 | 动作 | 声音 |
| --- | --- | --- | --- | --- |
| 0 毫秒 | `Serious` | `SoftWhite` | `None` | `None` |
| 200 毫秒 | `Listen` | `SoftWhite` | `None` | 发送 `listen start` |
| 用户说话期间 | `Listen` | `SoftWhite` | `None` | 铜豆一边采音、一边 Opus 编码、一边 WebSocket 发送 |
| 用户说完后 | `Serious` | `WeakBreath` | `TinyNod` | 发送 `listen stop` |
| 收到 `tts start` | `Awake` | `SoftWhite` | `Nod` | 准备说话，等待第一包 Opus |
| 收到第一包 Opus 并写入 I2S | `Awake` | `SoftWhite` | `Nod` | 开始播放服务端语音 |
| 收到 `tts stop` | `Smile` | `WeakBreath` | `None` | 回待机 |

实现要求：

- 按钮 `5` 触发 `RealtimeVoiceService.startTurn()`。
- 固件发送 `listen start`。
- 用户说话时，固件每 `60` 毫秒发送一包 Opus 音频。
- 采音、Opus 编码、WebSocket 发送必须同时跑，不能等整句话录完再处理。
- 固件发送 `listen stop`。
- 服务端必须使用流式 ASR、流式 LLM、流式 TTS。
- 服务端返回语音包后，铜豆一边接收、一边解码、一边播放。
- 第一版按半双工处理：听的时候不播，播的时候不录。
- 如果铜豆正在说话时再次点 `5`，先发 `abort`，清空本地播放队列，再进入新一轮聆听。

注意：

- 铜豆只播摘要，不在固件里登录邮箱。
- 邮件、日程、电脑任务这类外部内容，后续由本地助手或 `MCP` 负责整理成事件。
- 演示视频里的按钮 `5` 必须走真实麦克风和小智服务端，不用预录摘要代替。

### 8.6 按钮 6：嘴硬小舞步

用途：

> 视频动作高潮，展示电机、结构和黄铜质感。

触发台词：

用户说：

> “扭一个。”

铜豆表演中台词：

> “左三下，右三下，铜豆扭扭不白忙。”

表演后台词：

> “跳完了，拿奶茶钱。”

时间轴：

| 时间 | 表情 | 灯光 | 动作 | 声音 |
| --- | --- | --- | --- | --- |
| 0 毫秒 | `Proud` | `WarmWake` | `None` | `None` |
| 300 毫秒 | `Smile` | `SoftWhite` | `CheekyDance` | `DanceShowDomestic` |
| 1300 毫秒 | `Proud` | `WeakBreath` | `None` | `DemoDancePay` |
| 3000 毫秒 | `Smile` | `WeakBreath` | `None` | `None` |

实现要求：

- 动作只原地小幅左右律动。
- 不前进。
- 不连续循环。
- 总时长控制在 0.8 到 1 秒。
- 拍摄版优先做成高频小幅震颤，不做大幅前后乱晃。
- 正反转交替频率可以适当调高，单次脉冲时间要缩短。
- 左右轮的正反转节奏要尽量对称，避免身体慢慢偏向一边。
- 不点名具体人物，不做政治表达。
- 音乐不要直接使用受版权限制的成品歌曲，优先自制节奏音或哼唱感音效。

拍摄防滑处理：

- 光滑桌面上，轮胎可以套小橡皮圈增加摩擦力。
- 也可以在铜豆站位处贴一小块微磨砂隐形胶带。
- 胶带不要进入画面主体，不要遮住黄铜结构。
- 目标是在 1.5 秒以内的表演里，铜豆始终留在相机焦点中心。

需要新增或复用：

- 已有动作：`CheekyDance`。
- 已有台词：`DanceShowDomestic`。
- 建议新增台词：`DemoDancePay`。

### 8.8 按钮 0：停止并回待机

用途：

> 拍摄控场。

执行内容：

- 立即停止电机。
- 停止当前场景时间轴。
- 灯光回低亮或关闭。
- 屏幕回待机眼。
- 声音队列停止或不再追加新声音。

待机表现：

- 低亮灯。
- 偶尔眨眼。
- 不说话。
- 不主动移动。

## 10. 实施顺序

### 第一步：打通网页触发

目标：

- 手机能打开 `/demo`。
- 点击按钮后，固件能收到 `id`。
- 串口日志能打印当前场景编号。

完成标志：

- 手机点 `1`，串口出现 `demo scene 1`。
- 手机点 `0`，串口出现 `demo stop`。

### 第二步：接入剧情播放器

目标：

- `DemoScenePlayer` 能保存当前场景。
- 能按 `atMs` 执行步骤。
- 能中断并切换场景。

完成标志：

- `1` 到 `7` 能依次触发不同 `ScenarioPlan`。
- `0` 能马上回待机。

### 第三步：补齐表情、灯光、动作

目标：

- 深夜、清晨、邮件、小舞步、众筹收尾都有不同视觉表现。

完成标志：

- 不听声音，只看铜豆，也能大概看出它在干什么。

### 第四步：接入小智实时语音

目标：

- 按钮 `5` 能启动一轮实时语音。
- 铜豆能在用户说话时持续采音、持续 Opus 编码、持续发给小智服务端。
- 小智服务端能流式语音识别、流式大模型输出、流式文字转语音。
- 铜豆能边接收边播放小智服务端返回的语音。
- 服务端优先选择低首响组合：讯飞流式 ASR、qwen-flash 或 qwen-turbo、火山双流式 TTS 或讯飞流式 TTS。

完成标志：

- 用户对铜豆说“刚才什么邮件？”。
- 用户说话期间，铜豆持续发 Opus 包。
- 服务端能边收边识别这句话。
- 铜豆播出的回答来自服务端，而且不是等完整音频文件生成后才播放。
- 从用户说完到铜豆开始出声，目标控制在 `1.5` 秒左右，超过 `3` 秒就要继续查链路。

### 第五步：补齐固定剧情声音

目标：

- 除按钮 `5` 外，每个关键剧情有固定台词。
- 台词短、准、有铜豆味。

完成标志：

- `1`、`2`、`3`、`6`、`7` 都能播出对应声音。

### 第六步：拍摄排练

目标：

- 手机藏在镜头外。
- 由操盘手按 `1` 到 `7`。
- 铜豆按视频分镜稳定表演。

完成标志：

- 完整走一遍 60 秒视频，不需要重启铜豆。

## 12. 后续迁移

演示版里有价值的内容，后续可以迁移到正式固件：

| 演示内容 | 正式固件归宿 |
| --- | --- |
| 深夜加班提醒 | `铜豆剧情包.md` 的下班提醒剧情 |
| 清晨唤醒 | 用户到桌前或开机上线剧情 |
| 邮件静默提醒 | 本地助手或 `MCP` 邮件事件 |
| 实时语音邮件摘要 | 电脑端小智服务端或后续 `MCP` 工具结果播报 |
| 嘴硬小舞步 | 彩蛋剧情 |
| 众筹收尾 | 仅保留在演示固件，不进日常固件 |

迁移原则：

- 正式固件保留“事件触发剧情”的结构。
- 演示专用台词不直接变成日常默认台词。
- 众筹收尾只属于拍摄和展会演示，不进入用户日常提醒。
