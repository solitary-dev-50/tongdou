# 演示版固件实施文档

这份文档只负责一件事：

> 把铜豆众筹视频用的演示版固件做清楚。

它不是正式固件完整需求，也不是网页配置系统说明。  
大白话说：正式固件负责长期生活，演示版固件负责让铜豆在镜头前稳定、好控、像活的。

---

## 1. 一句话结论

演示版固件采用：

> **铜豆自建无线热点 + 手机浏览器数字按钮页面 + 1 到 8 场景触发 + 非阻塞剧情播放器。**

手机只是拍摄时的遥控器。  
铜豆在画面里表现为一个独立工作的桌面搭子，不需要露出电脑连接线，也不需要展示复杂后台。

---

## 2. 演示目标

这版固件优先服务海外短视频和海外众筹页面。

当前演示固件只做海外版。
国内版台词、奶茶梗和中文传播素材先留在剧情素材库里，不进入这轮演示固件。

必须做到：

- 一打开电源，铜豆能进入待机状态。
- 手机连上铜豆热点后，可以打开演示页面。
- 页面只显示大号数字按钮。
- 点 `1` 到 `8`，铜豆播放对应演示剧情；按钮 `6` 会展开二级按钮 `1` 到 `5`。
- 点 `0`，铜豆停止当前剧情并回到待机。
- 每个剧情都按固定时间轴执行屏幕、灯光、电机和声音。
- 每次触发同一个按钮，表现尽量一致，方便反复拍摄。

明确不做：

- 不做开空调施法。
- 不做智能音箱路线。
- 不做全天候唤醒和闲聊。
- 不用预录摘要冒充大模型回答。
- 不让网页直接控制灯、电机、屏幕的底层细节。
- 不做国内版演示按钮。
- `first_summon_nightmare` 不接实时语音，不使用 TTS，不依赖云端。
- `confused_accountant_global` 只是固定拍摄剧情，不接实时语音，不使用 TTS，不依赖云端，不写入真实账本。
- 正式提醒、日程、待办不能使用糊涂账房先生的随机或含糊逻辑。

## 3. 视频结构

视频采用 `AIDA` 模型。  
这里的 `AIDA` 是经典营销结构：

- `Attention`：吸引注意力。
- `Interest`：激发兴趣。
- `Desire`：勾起欲望。
- `Action`：促成行动。

| 视频段落 | 时间 | 演示按钮 | 画面作用 |
| --- | --- | --- | --- |
| 黄金开头 | 0 到 8 秒 | `1`、`2` | 用海外深夜加班嘴欠提醒抓住注意力 |
| 情绪过渡 | 8 到 18 秒 | `3` | 展示清晨唤醒和温柔一面 |
| 核心卖点 | 18 到 38 秒 | `4`、`5` | 展示邮件摘要和不打扰工作流 |
| 第二条海外短视频 | 8 到 28 秒 | `6` | 展示糊涂账房先生、OLED 账目动画和铜豆欠揍性格 |
| 信任收尾 | 48 到 58 秒 | 拍实物和控制台 | 展示黄铜件、焊接、治具、网页控制 |
| 行动召唤 | 58 到 60 秒 | `7` | 用财迷眼和台词收口 |

## 4. 控制方式

### 4.1 固件启动后

铜豆启动后创建无线热点：

```txt
TongDou-Demo
```

手机连接这个热点后，浏览器打开：

```txt
http://192.168.4.1/demo
```

如果后续希望更省事，可以让根路径 `/` 自动跳转到 `/demo`。

### 4.2 演示页面

页面只需要大按钮：

```txt
1  2  3  4
5  6  7  8
0
```

页面显示内容：

- 当前连接状态。
- 当前播放场景编号。
- `1` 到 `8` 场景按钮。
- `0` 停止按钮。

页面不要做复杂配置。  
这个页面是拍摄遥控器，不是正式用户后台。

按钮 `6` 的二级按钮：

| 二级按钮 | 分支 | 场景名称 | 用途 |
| --- | --- | --- | --- |
| `6-1` | 正常销账 | `confused_accountant_clear` | 划掉一笔债，再趁机问要不要结清 |
| `6-2` | 趁机敲诈 | `confused_accountant_extort` | 声称触摸造成情绪损失，加一杯咖啡 |
| `6-3` | 收受贿赂 | `confused_accountant_bribe` | 偷偷清掉三笔债，让用户别告诉审计 |
| `6-4` | 选择性健忘 | `confused_accountant_forgetful` | 账本写三，记忆说五，硬算成五 |
| `6-5` | 荒谬小数点 | `confused_accountant_pi` | 算成 3.1415 杯，拒绝向下取整 |

这些分支都只是演示剧情。底层账本不改，不写入 Flash/NVS，不影响正式提醒、日程和待办。

## 5. 网页接口

演示版接口独立于正式网页配置接口。

建议接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/demo` | 返回演示控制页面 |
| `POST` | `/api/demo/scene` | 触发某个演示场景 |
| `GET` | `/api/demo/status` | 查询当前演示状态 |

`POST /api/demo/scene` 请求体：

```json
{
  "id": 1
}
```

按钮 `6` 二级分支请求体：

```json
{
  "id": 6,
  "variant": 1
}
```

返回：

```json
{
  "ok": true,
  "scene": "night_gossip_hook",
  "playing": true
}
```

说明：

- 按钮 `5` 使用本地预录邮件摘要，不接实时语音。
- 邮件、日程、电脑任务这类外部内容，由电脑端小智服务端或后续 `MCP` 工具整理。
- `MCP` 是模型上下文协议，大白话就是让电脑端助手能调用工具、把结果交给铜豆。

## 6. 固件模块设计

演示版固件可以新增 `firmware/src/demo` 目录。

### 6.1 文件职责

| 文件 | 只负责什么 |
| --- | --- |
| `DemoSceneId.h` | 定义演示场景编号和名称 |
| `DemoSceneTypes.h` | 定义演示时间轴的数据结构 |
| `DemoSceneLibrary.h/.cpp` | 保存 1 到 8 的固定演示剧情 |
| `DemoScenePlayer.h/.cpp` | 按时间轴非阻塞播放剧情 |
| `DemoWebPage.h/.cpp` | 提供演示页面和演示接口 |

单一职责要求：

- `DemoWebPage` 只接收按钮请求，不直接控制硬件。
- `DemoSceneLibrary` 只保存剧情数据，不负责播放。
- `DemoScenePlayer` 只按时间播放，不解析网页请求。
- 硬件层仍然只管硬件，不知道“众筹收尾”“吃瓜开头”是什么。

### 6.2 依赖关系

推荐关系：

```txt
WebConfigServer
  -> DemoWebPage
    -> DemoScenePlayer
      -> ScenarioExecutor
        -> FaceDisplay / LedPixel / MotorDriver / AudioOutput
```

大白话说：

- 网页负责按按钮。
- 演示页负责把按钮变成场景编号。
- 剧情播放器负责按时间喊动作。
- 正式剧情执行器负责把动作交给屏幕、灯、电机和声音。

这样做的好处是：  
演示版不会绕过现有剧情执行层，以后可以把有价值的演示剧情平滑搬进正式剧情包。

---

## 7. 时间轴数据结构

每个场景是一组步骤。

建议结构：

```cpp
struct DemoSceneStep {
  uint16_t atMs;
  FaceAction face;
  LightAction light;
  MotionAction motion;
  VoiceLine voice;
  uint16_t durationMs;
};
```

字段解释：

| 字段 | 含义 |
| --- | --- |
| `atMs` | 从场景开始算，第几毫秒执行 |
| `face` | 屏幕表情动作 |
| `light` | 灯光动作 |
| `motion` | 电机动作 |
| `voice` | 台词或声音 |
| `durationMs` | 本步建议持续时间 |

执行规则：

- `DemoScenePlayer` 每轮 `update()` 检查时间。
- 到点后，把当前步骤转成 `ScenarioPlan`。
- 调用 `ScenarioExecutor.execute(plan)`。
- 播放期间不使用 `delay()`。
- 新场景触发时，可以中断旧场景并从新场景第一步开始。
- `0` 必须立刻停止动作、熄灭或回待机。

## 8. 场景详细设计

### 8.0 按钮 8：First Summon Nightmare / 魔头诞生

用途：

> 首次上电和主动召唤仪式，让铜豆像被造物者从虚无里焊醒的小魔头。

触发条件：

- 第一次上电时，如果 `first_summon_played` 不是 `true`，自动播放一次。
- 后续只能通过按钮 `8` 或调试指令 `summon` / `nightmare` 主动触发。
- 普通重启不反复播放完整召唤剧情。

音频文件：

```txt
demo_00_first_summon.wav
```

英文台词：

> Did you...
>
> summon me from the void?
>
> Good.
>
> Foolish human.
>
> Your desktop nightmare...
>
> begins now!
>
> Gah-ha-ha-ha!

时间轴：

| 时间 | 表情 | 灯光 | 动作 | 声音 |
| --- | --- | --- | --- | --- |
| 0 毫秒 | `Sleep` | `Off` | `None` | `None` |
| 300 毫秒 | `Sleep` | `DimWarm` | `None` | `None` |
| 700 毫秒 | `WakeUp` | `WeakBreath` | `None` | `None` |
| 1100 毫秒 | `Surprised` | `WarmWake` | `TinyShake` | `None` |
| 1500 毫秒 | `Fierce` | `DimWarm` | `None` | `DemoFirstSummonNightmare` |
| 2600 毫秒 | `Fierce` | `DimWarm` | `SummonSpinBrake` | `None` |
| 3400 毫秒 | `Squint` | `DimCyan` | `None` | `None` |
| 5200 毫秒 | `Proud` | `WeakBreath` | `Stop` | `None` |

实现要求：

- 所有步骤非阻塞，不允许 `delay()`。
- 原地转圈总时长控制在 600 到 900 毫秒。
- 动作结束必须先短刹车，再 `motor stop`。
- 如果中途按 `0`，必须立即停止电机、停止音频、回待机。
- 不接 ASR、LLM、TTS，不走小智实时语音链路。

调试入口：

- `summon`：手动触发召唤剧情。
- `nightmare`：手动触发召唤剧情。
- `reset_first_summon`：清除首次播放标记，方便重新测试首次上电。

### 8.6 按钮 6：糊涂的账房先生 / The Confused Accountant

用途：

> 恶魔降临之后的第二条海外短视频剧情，展示铜豆像一个糊涂、固执、只会把错误算到用户头上的老账房先生。

当前实现是固定演示剧情。按钮 `6` 模拟用户触摸金色 Logo 还债，不接真实触摸输入，不写入真实账本。

按钮 `6` 不直接播放剧情，只展开二级按钮。二级按钮 `1` 到 `5` 分别播放五个固定分支。

录音风格：

- 英文。
- 年轻男声，小恶魔风格。
- 微沙哑、狡黠、斤斤计较。
- 不是老人声音，不是恐怖恶魔。
- `my little ledger` 像真的藏着一本私人黑账。
- `Found it!` 要突然兴奋。
- `No.` 后停顿。
- `I don't round down.` 要理直气壮、欠揍。
- 不使用受版权保护的音乐。
- 不使用政治人物名字。

音效：

- `rustle_pages`：真实纸张快速翻页声，约 0.8 到 1.2 秒。
- `scratch_pencil`：铅笔用力划掉一行，约 0.6 到 1.0 秒。
- 综合剧情仍建议使用完整音频 `demo_06_confused_accountant.pcm`，保证语音、音效和 OLED 同步。
- 当前尚未提供这段综合音频，因此不启用 `Full Story` 按钮，也不把五段分支音频直接拼成冗长剧情。

实现要求：

- 不再跳舞，不再转身，不再背对用户。
- OLED 必须能显示横线罢工眼、震惊圆眼、怀疑斜眼、翻账扫描、债务 `3`、划线、债务 `2`、`3.1415` 和贱笑。
- 债务划线必须是 500 到 800 毫秒的像素动画，不能瞬间切换。
- 算不清账时使用 `AccountantConfusedFidget`，表现烦躁翻账。
- 想敲诈用户结清剩余咖啡债时使用 `AccountantExtortLean`，表现小幅前探。
- 重新算出 `3.1415` 时使用 `AccountantStubbornWiggle`，表现胡搅蛮缠。
- 结尾只保留一次 `TinySmugWiggle`，左右各轻微摆一次，完成后立刻停止。
- 当前样机实测 `PWM 160` 以下几乎无明显动作，微动使用约 `185` 的短脉冲。
- 场景 `6` 的车身动作由双轮共同受力，换向前必须先 `Stop` 并保留停顿，不使用单轮支点和硬刹车。
- 表演结束后关闭灯，OLED 回到自然待机眼，不继续保持表演姿态。
- 不高频抽搐，不明显前进，不追求转身。
- 场景必须可中断，`0` 键必须立即停止音频和电机。
- 不接 TTS，不接实时语音，不接云端。
- 不做真实金色 Logo 触摸输入。
- 不做债务持久化，不写 Flash 或 NVS 账本。
- 不做随机概率分支，不真正修改用户债务。
- 不拦截 MCP 指令，不影响正式提醒、日程、待办。

需要新增或复用：

- 新增场景：`confused_accountant_global`。
- 新增台词：`DemoConfusedAccountant`。
- 新增动作：`TinySmugWiggle`。
- 旧的舞蹈动作可以保留给其它彩蛋，但按钮 `6` 不再调用。

## 10. 实施顺序

- 手机点 `0`，串口出现 `demo stop`。

目标：

- `DemoScenePlayer` 能保存当前场景。
- 能按 `atMs` 执行步骤。
- 能中断并切换场景。

完成标志：

- `1` 到 `7` 能依次触发不同 `ScenarioPlan`。
- `0` 能马上回待机。

### 第三步：补齐表情、灯光、动作

目标：

- 深夜、清晨、邮件、糊涂账房先生、众筹收尾都有不同视觉表现。

完成标志：

- 不听声音，只看铜豆，也能大概看出它在干什么。

- 按钮 `5` 使用本地预录音频。

### 第五步：补齐固定剧情声音

- 每个需要说话的关键剧情都有固定台词。

- `1`、`2`、`3`、`5`、`6`、`7`、`8` 都能播出对应海外版声音。

### 第六步：拍摄排练

目标：

- 手机藏在镜头外。
- 由操盘手按 `1` 到 `8`。
- 铜豆按视频分镜稳定表演。

完成标志：

- 完整走一遍 60 秒视频，不需要重启铜豆。

## 12. 后续迁移

演示版里有价值的内容，后续可以迁移到正式固件：

| 演示内容 | 正式固件归宿 |
| --- | --- |
| 海外深夜加班提醒 | `铜豆剧情包.md` 的下班提醒剧情素材 |
| 清晨唤醒 | 用户到桌前或开机上线剧情 |
| 邮件静默提醒 | 本地助手或 `MCP` 邮件事件 |
| 预录邮件摘要 | 后续可替换为电脑端小智服务端或 `MCP` 工具结果播报 |
| 糊涂的账房先生 | 可作为正式固件的咖啡债人格彩蛋，不进入默认日常提醒 |
| 海外众筹收尾 | 仅保留在演示固件，不进日常固件 |
| `first_summon_nightmare` | 可迁移到正式固件的首次上电剧情，日常普通开机不能默认反复播放 |

迁移原则：

- 正式固件保留“事件触发剧情”的结构。
- 演示专用台词不直接变成日常默认台词。
- 众筹收尾只属于拍摄和展会演示，不进入用户日常提醒。
- `confused_accountant_global` 后续如果迁移，只能作为咖啡债隐藏彩蛋。
- 真实提醒、日程、待办绝不能随机或含糊，也不能被糊涂账房先生逻辑影响。
