# 演示版固件实施文档

这份文档只负责一件事：

> 把铜豆众筹视频用的演示版固件做清楚。

它不是正式固件完整需求，也不是网页配置系统说明。  
大白话说：正式固件负责长期生活，演示版固件负责让铜豆在镜头前稳定、好控、像活的。

---

## 1. 一句话结论

演示版固件采用：

> **铜豆自建无线热点 + 手机浏览器数字按钮页面 + 1 到 8 场景触发 + 非阻塞剧情播放器。**

手机只是拍摄时的遥控器。  
铜豆在画面里表现为一个独立工作的桌面搭子，不需要露出电脑连接线，也不需要展示复杂后台。

---

## 2. 演示目标

这版固件优先服务海外短视频和海外众筹页面。

当前演示固件只做海外版。
国内版台词、奶茶梗和中文传播素材先留在剧情素材库里，不进入这轮演示固件。

必须做到：

- 一打开电源，铜豆能进入待机状态。
- 手机连上铜豆热点后，可以打开演示页面。
- 页面只显示大号数字按钮。
- 点 `1` 到 `8`，铜豆播放对应演示剧情。
- 点 `0`，铜豆停止当前剧情并回到待机。
- 每个剧情都按固定时间轴执行屏幕、灯光、电机和声音。
- 每次触发同一个按钮，表现尽量一致，方便反复拍摄。

明确不做：

- 不做开空调施法。
- 不做智能音箱路线。
- 不做全天候唤醒和闲聊。
- 不用预录摘要冒充大模型回答。
- 不让网页直接控制灯、电机、屏幕的底层细节。
- 不做国内版演示按钮。
- `first_summon_nightmare` 不接实时语音，不使用 TTS，不依赖云端。

---

## 3. 视频结构

视频采用 `AIDA` 模型。  
这里的 `AIDA` 是经典营销结构：

- `Attention`：吸引注意力。
- `Interest`：激发兴趣。
- `Desire`：勾起欲望。
- `Action`：促成行动。

| 视频段落 | 时间 | 演示按钮 | 画面作用 |
| --- | --- | --- | --- |
| 黄金开头 | 0 到 8 秒 | `1`、`2` | 用海外深夜加班嘴欠提醒抓住注意力 |
| 情绪过渡 | 8 到 18 秒 | `3` | 展示清晨唤醒和温柔一面 |
| 核心卖点 | 18 到 38 秒 | `4`、`5` | 展示邮件摘要和不打扰工作流 |
| 视觉高潮 | 38 到 48 秒 | `6` | 展示嘴硬小舞步、电机和黄铜结构质感 |
| 信任收尾 | 48 到 58 秒 | 拍实物和控制台 | 展示黄铜件、焊接、治具、网页控制 |
| 行动召唤 | 58 到 60 秒 | `7` | 用财迷眼和台词收口 |

## 4. 控制方式

### 4.1 固件启动后

铜豆启动后创建无线热点：

```txt
TongDou-Demo
```

手机连接这个热点后，浏览器打开：

```txt
http://192.168.4.1/demo
```

如果后续希望更省事，可以让根路径 `/` 自动跳转到 `/demo`。

### 4.2 演示页面

页面只需要大按钮：

```txt
1  2  3  4
5  6  7  8
0
```

页面显示内容：

- 当前连接状态。
- 当前播放场景编号。
- `1` 到 `8` 场景按钮。
- `0` 停止按钮。

页面不要做复杂配置。  
这个页面是拍摄遥控器，不是正式用户后台。

### 4.3 按钮映射

| 按钮 | 场景编号 | 场景名称 | 用途 |

| `1` | `late_night_doghouse_hook` | 海外深夜加班开头 | 视频开场抓人 |

## 5. 网页接口

演示版接口独立于正式网页配置接口。

建议接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/demo` | 返回演示控制页面 |
| `POST` | `/api/demo/scene` | 触发某个演示场景 |
| `GET` | `/api/demo/status` | 查询当前演示状态 |

`POST /api/demo/scene` 请求体：

```json
{
  "id": 1
}
```

返回：

```json
{
  "ok": true,
  "scene": "night_gossip_hook",
  "playing": true
}
```

说明：

- 按钮 `5` 使用本地预录邮件摘要，不接实时语音。
- 邮件、日程、电脑任务这类外部内容，由电脑端小智服务端或后续 `MCP` 工具整理。
- `MCP` 是模型上下文协议，大白话就是让电脑端助手能调用工具、把结果交给铜豆。

## 6. 固件模块设计

演示版固件可以新增 `firmware/src/demo` 目录。

### 6.1 文件职责

| 文件 | 只负责什么 |
| --- | --- |
| `DemoSceneId.h` | 定义演示场景编号和名称 |
| `DemoSceneTypes.h` | 定义演示时间轴的数据结构 |
| `DemoSceneLibrary.h/.cpp` | 保存 1 到 8 的固定演示剧情 |
| `DemoScenePlayer.h/.cpp` | 按时间轴非阻塞播放剧情 |
| `DemoWebPage.h/.cpp` | 提供演示页面和演示接口 |

单一职责要求：

- `DemoWebPage` 只接收按钮请求，不直接控制硬件。
- `DemoSceneLibrary` 只保存剧情数据，不负责播放。
- `DemoScenePlayer` 只按时间播放，不解析网页请求。
- 硬件层仍然只管硬件，不知道“众筹收尾”“吃瓜开头”是什么。

### 6.2 依赖关系

推荐关系：

```txt
WebConfigServer
  -> DemoWebPage
    -> DemoScenePlayer
      -> ScenarioExecutor
        -> FaceDisplay / LedPixel / MotorDriver / AudioOutput
```

大白话说：

- 网页负责按按钮。
- 演示页负责把按钮变成场景编号。
- 剧情播放器负责按时间喊动作。
- 正式剧情执行器负责把动作交给屏幕、灯、电机和声音。

这样做的好处是：  
演示版不会绕过现有剧情执行层，以后可以把有价值的演示剧情平滑搬进正式剧情包。

## 7. 时间轴数据结构

每个场景是一组步骤。

建议结构：

```cpp
struct DemoSceneStep {
  uint16_t atMs;
  FaceAction face;
  LightAction light;
  MotionAction motion;
  VoiceLine voice;
  uint16_t durationMs;
};
```

字段解释：

| 字段 | 含义 |
| --- | --- |
| `atMs` | 从场景开始算，第几毫秒执行 |
| `face` | 屏幕表情动作 |
| `light` | 灯光动作 |
| `motion` | 电机动作 |
| `voice` | 台词或声音 |
| `durationMs` | 本步建议持续时间 |

执行规则：

- `DemoScenePlayer` 每轮 `update()` 检查时间。
- 到点后，把当前步骤转成 `ScenarioPlan`。
- 调用 `ScenarioExecutor.execute(plan)`。
- 播放期间不使用 `delay()`。
- 新场景触发时，可以中断旧场景并从新场景第一步开始。
- `0` 必须立刻停止动作、熄灭或回待机。

## 8. 场景详细设计

### 8.0 按钮 8：First Summon Nightmare / 魔头诞生

用途：

> 首次上电和主动召唤仪式，让铜豆像被造物者从虚无里焊醒的小魔头。

触发条件：

- 第一次上电时，如果 `first_summon_played` 不是 `true`，自动播放一次。
- 后续只能通过按钮 `8` 或调试指令 `summon` / `nightmare` 主动触发。
- 普通重启不反复播放完整召唤剧情。

音频文件：

```txt
demo_00_first_summon.wav
```

英文台词：

> Did you...
>
> summon me from the void?
>
> Good.
>
> Foolish human.
>
> Your desktop nightmare...
>
> begins now!
>
> Gah-ha-ha-ha!

时间轴：

| 时间 | 表情 | 灯光 | 动作 | 声音 |
| --- | --- | --- | --- | --- |
| 0 毫秒 | `Sleep` | `Off` | `None` | `None` |
| 300 毫秒 | `Sleep` | `DimWarm` | `None` | `None` |
| 700 毫秒 | `WakeUp` | `WeakBreath` | `None` | `None` |
| 1100 毫秒 | `Surprised` | `WarmWake` | `TinyShake` | `None` |
| 1500 毫秒 | `Fierce` | `DimWarm` | `None` | `DemoFirstSummonNightmare` |
| 2600 毫秒 | `Fierce` | `DimWarm` | `SummonSpinBrake` | `None` |
| 3400 毫秒 | `Squint` | `DimCyan` | `None` | `None` |
| 5200 毫秒 | `Proud` | `WeakBreath` | `Stop` | `None` |

实现要求：

- 所有步骤非阻塞，不允许 `delay()`。
- 原地转圈总时长控制在 600 到 900 毫秒。
- 动作结束必须先短刹车，再 `motor stop`。
- 如果中途按 `0`，必须立即停止电机、停止音频、回待机。
- 不接 ASR、LLM、TTS，不走小智实时语音链路。

调试入口：

- `summon`：手动触发召唤剧情。
- `nightmare`：手动触发召唤剧情。
- `reset_first_summon`：清除首次播放标记，方便重新测试首次上电。

### 8.6 按钮 6：嘴硬小舞步

用途：

> 视频动作高潮，展示电机、结构和黄铜质感。

触发台词：

用户说：

> “Do a little dance.”

铜豆表演中台词：

> “I'm not dancing... you're dancing.”

表演后台词：

> “Done. Pay up. No free shows. A coffee works too.”

时间轴：

| 时间 | 表情 | 灯光 | 动作 | 声音 |
| --- | --- | --- | --- | --- |
| 0 毫秒 | `Proud` | `WarmWake` | `None` | `None` |
| 300 毫秒 | `Smile` | `SoftWhite` | `CheekyDance` | `DanceShowGlobal` |
| 1300 毫秒 | `Proud` | `WeakBreath` | `None` | `DemoDanceCoffeePay` |
| 3000 毫秒 | `Smile` | `WeakBreath` | `None` | `None` |

实现要求：

- 动作只原地小幅左右律动。
- 不前进。
- 不连续循环。
- 总时长控制在 0.8 到 1 秒。
- 拍摄版优先做成高频小幅震颤，不做大幅前后乱晃。
- 正反转交替频率可以适当调高，单次脉冲时间要缩短。
- 左右轮的正反转节奏要尽量对称，避免身体慢慢偏向一边。
- 不点名具体人物，不做政治表达。
- 音乐不要直接使用受版权限制的成品歌曲，优先自制节奏音或哼唱感音效。

拍摄防滑处理：

- 光滑桌面上，轮胎可以套小橡皮圈增加摩擦力。
- 也可以在铜豆站位处贴一小块微磨砂隐形胶带。
- 胶带不要进入画面主体，不要遮住黄铜结构。
- 目标是在 1.5 秒以内的表演里，铜豆始终留在相机焦点中心。

需要新增或复用：

- 已有动作：`CheekyDance`。
- 建议新增台词：`DanceShowGlobal`、`DemoDanceCoffeePay`。

### 8.8 按钮 0：停止并回待机

用途：

> 拍摄控场。

执行内容：

- 立即停止电机。
- 停止当前场景时间轴。
- 灯光回低亮或关闭。
- 屏幕回待机眼。
- 声音队列停止或不再追加新声音。

待机表现：

- 低亮灯。
- 偶尔眨眼。
- 不说话。
- 不主动移动。

## 10. 实施顺序

### 第一步：打通网页触发

目标：

- 手机能打开 `/demo`。
- 点击按钮后，固件能收到 `id`。
- 串口日志能打印当前场景编号。

完成标志：

- 手机点 `1`，串口出现 `demo scene 1`。
- 手机点 `0`，串口出现 `demo stop`。

### 第二步：接入剧情播放器

目标：

### 第三步：补齐表情、灯光、动作

目标：

- 深夜、清晨、邮件、小舞步、众筹收尾都有不同视觉表现。

完成标志：

- 不听声音，只看铜豆，也能大概看出它在干什么。

### 第四步：补齐预录邮件摘要

目标：

- 按钮 `5` 使用本地预录音频。
- 不接 ASR、LLM、TTS。
- 不依赖服务端和网络。

完成标志：

- 点击按钮 `5` 后，铜豆播放固定邮件摘要录音。

### 第五步：补齐固定剧情声音

目标：

- 每个需要说话的关键剧情都有固定台词。

完成标志：

- `1`、`2`、`3`、`5`、`6`、`7`、`8` 都能播出对应海外版声音。

### 第六步：拍摄排练

目标：

- 手机藏在镜头外。
- 由操盘手按 `1` 到 `8`。
- 铜豆按视频分镜稳定表演。

完成标志：

- 完整走一遍 60 秒视频，不需要重启铜豆。

## 12. 后续迁移

演示版里有价值的内容，后续可以迁移到正式固件：

| 演示内容 | 正式固件归宿 |
| --- | --- |
| 海外深夜加班提醒 | `铜豆剧情包.md` 的下班提醒剧情素材 |
| 清晨唤醒 | 用户到桌前或开机上线剧情 |
| 邮件静默提醒 | 本地助手或 `MCP` 邮件事件 |
| 预录邮件摘要 | 后续可替换为电脑端小智服务端或 `MCP` 工具结果播报 |
| 海外小舞步 | 彩蛋剧情的海外版素材 |
| 海外众筹收尾 | 仅保留在演示固件，不进日常固件 |
| `first_summon_nightmare` | 可迁移到正式固件的首次上电剧情，日常普通开机不能默认反复播放 |

迁移原则：

- 正式固件保留“事件触发剧情”的结构。
- 演示专用台词不直接变成日常默认台词。
- 众筹收尾只属于拍摄和展会演示，不进入用户日常提醒。
