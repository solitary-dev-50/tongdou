# 表情系统

这份文档规定铜豆屏幕眼睛和表情的风格。

表情资源包、资源命名、Font Awesome 和自定义眼神资源的分工，见 `docs/表情包设计.md`。

大白话说：

> 铜豆的眼神比台词更重要。眼神对了，它才像活的。

---

## 1. 表情定位

铜豆的屏幕优先显示“眼睛”，不是长文字。

原因：

- 眼睛识别快。
- 小屏幕上文字容易拥挤。
- 表情更容易形成角色感。
- 当前屏幕是 `0.96` 寸 `OLED`，更适合黑白小眼神，不适合高帧率动态大表情包。

文字可以作为辅助，但不要把屏幕做成公告栏。

第一版路线：

- 做低帧数眼神动画。
- 用几帧切换表达情绪。
- 不直接搬板机的动态 `Emote` 表情包。
- 保留表情编号接口，后续如果换屏再升级显示实现。

---

## 2. 第一版表情列表

| 表情编号 | 名称 | 用途 |
| --- | --- | --- |
| `face_sleep` | 睡觉眼 | 无人、低功耗、安静待机 |
| `face_wake` | 睁眼 | 用户到达、启动上线 |
| `face_smile` | 开心眼 | 完成奖励、确认收到 |
| `face_serious` | 认真眼 | 会议提醒、重要提醒 |
| `face_roll_eyes` | 翻白眼 | 推迟、轻微吐槽 |
| `face_wronged` | 委屈眼 | 安静模式、被用户凶 |
| `face_tired` | 累瘫眼 | 装累、低电量、施法结束 |
| `face_shock` | 惊恐眼 | 拍桌子、异常声音 |
| `face_listen` | 倾听眼 | 唤醒后等待命令 |
| `face_think` | 认真眼 | 已听完，等待服务器回复 |
| `face_speak` | 开心眼 | 铜豆正在播放回复或告别语 |

实时语音状态只使用眼神，不在小屏幕上显示“监听中”“思考中”等长文字。当前固件中，`face_listen` 使用独立倾听眼；`face_think` 复用认真眼；`face_speak` 复用开心眼。

---

## 3. 表情风格

建议风格：

- 简单。
- 粗线条。
- 黑白优先。
- 少文字。
- 帧数少但节奏准。

不要：

- 太复杂的小图。
- 过多中文小字。
- 长时间闪烁。
- 每秒变很多表情。

---

## 4. 表情切换节奏

### 4.1 唤醒

```txt
睡觉眼 -> 半睁眼 -> 睁眼 -> 倾听眼
```

时间建议：

- 600 到 1200 毫秒。

### 4.2 确认完成

```txt
认真眼 -> 开心眼 -> 待机眼
```

时间建议：

- 800 到 1500 毫秒。

### 4.3 推迟提醒

```txt
认真眼 -> 翻白眼 -> 待机眼
```

时间建议：

- 800 到 1200 毫秒。

### 4.4 安静模式

```txt
睁眼 -> 委屈眼 -> 闭眼
```

时间建议：

- 600 到 1000 毫秒。

### 4.5 实时语音

```txt
倾听眼 -> 认真眼 -> 开心眼 -> 倾听眼
```

- 连续对话轮次之间不插入睡觉眼，避免屏幕闪一下造成“已经退出”的误解。
- 服务端正常告别、最后一段语音播放完成后，才切到睡觉眼。
- 识别或网络失败时，交给现有失败补救剧情，不由语音状态反馈覆盖。
- 提醒正文显示的优先级高于语音状态，不能被倾听眼盖掉。

---

## 5. 优先级

表情优先级从高到低：

1. 故障或安全提示。
2. 低电量。
3. 用户正在交互。
4. 当前提醒。
5. 剧情和彩蛋。
6. 待机。

高优先级可以打断低优先级。

例如：

- 正在搞怪时低电量，立刻切低电量。
- 安静模式下，不显示夸张彩蛋表情。

---

## 6. 和剧情模块的关系

剧情模块只输出表情编号。

例如：

```txt
ScenarioPlan.face = FaceAction::RollEyes
```

屏幕模块负责把编号变成真正像素动画。

禁止：

- 剧情模块直接画像素。
- 屏幕模块自己决定剧情。

---

## 7. 检查清单

新增表情前检查：

1. 不看台词，用户能不能大概看懂情绪？
2. 小屏幕上是否清楚？
3. 是否能和灯光、电机配合？
4. 是否会过度闪烁？
5. 是否符合“嘴凶动作怂”的角色？
6. 安静模式下是否有低打扰版本？
