# 系统架构

本文锁定当前固件架构边界。

## 一句话原则

铜豆固件按职责分层：硬件只管硬件，剧情只管表现，提醒只管时间，网页只管配置，`App` 只负责把它们接起来。

## 分层

```text
SystemBootstrap
  -> App

App
  -> Hardware
  -> Scenario
  -> Reminder
  -> Realtime Voice
  -> Web
  -> MCP
```

## App 职责

`App` 只做三件事：

1. 初始化模块。
2. 每轮调用模块更新。
3. 把事件交给剧情层。

`App` 不允许直接写：

- 具体灯效。
- 具体电机动作。
- 具体台词。
- 存储格式细节。
- 电池百分比算法。
- 网页接口细节。

## 应用命令层

应用命令层负责接收网页或 MCP 的高层命令，并转交给应用内部模块。

| 文件 | 职责 |
| --- | --- |
| `AppCommandService.*` | 承接剧情、人格模式和实时语音回合命令 |

它不解析网络协议，也不直接操作硬件。

## 启动层

启动层负责系统入口和启动编排。

| 文件 | 职责 |
| --- | --- |
| `SystemBootstrap.*` | 系统启动入口，负责调用 `boot()` 和 `run()` |

`main.cpp` 只创建 `SystemBootstrap`，不直接初始化具体模块。

## 硬件层

硬件层只负责把真实硬件包成简单接口。

| 文件 | 职责 |
| --- | --- |
| `HardwareManager.*` | 按顺序初始化硬件，并统一更新硬件诊断 |
| `AudioInput.*` | PDM 麦克风输入和音量诊断 |
| `AudioOutput.*` | NS4168 I2S 输出、`SPK_CTRL / IO15` 控制和测试音 |
| `AudioCuePlayer.*` | 本地提示音播放，负责选择内置提示音并交给音频输出 |
| `OggOpusDemuxer.*` | 只负责从 OGG 文件中拆出 Opus 音频包 |
| `BatteryMonitor.*` | 电池、USB、充电、充满检测 |
| `DisplayBus.*` | I2C 初始化 |
| `FaceDisplay.*` | OLED 表情显示 |
| `ImuSensor.*` | 读取 `QMI8658A` 姿态、倾斜、敲击和倾倒原始数据 |
| `LedPixel.*` | SK6812-EC20 控制 |
| `LogoTouchInput.*` | 读取铜豆 Logo 触摸输入，做基础滤波和触摸事件 |
| `MotorDriver.*` | AT8833CT 双电机控制、`MOTOR_SLEEP / IO42` 睡眠控制和 `MOTOR_FAULT / IO37` 故障检测 |
| `RadarSensor.*` | 雷达信号读取 |
| `HardwareSelfTestService.*` | 统一执行硬件自检命令 |

硬件层禁止知道剧情名。

V9 注意事项：

- OLED 和 `QMI8658A` 共用 `IO6/IO7` I2C，总线只能统一初始化。
- `LogoTouchInput` 只负责识别触摸，不负责“还债”“召唤”等剧情含义。
- `ImuSensor` 只负责输出姿态事件，不负责决定表情、灯光、动作或台词。
- `MotorDriver` 只负责电机输出、睡眠控制和 `nFAULT` 故障读取；检测到 `MOTOR_FAULT / IO37` 低电平时，上层应停止电机并进入降级处理。

## 诊断层

诊断层只负责把已有硬件接口组合成自检命令，方便串口和后续网页诊断复用。

| 文件 | 职责 |
| --- | --- |
| `HardwareSelfTestService.*` | 电池、雷达、麦克风、喇叭、灯和电机的自检入口 |

诊断层不保存配置，不决定剧情，不直接处理网页路由。

V9 诊断层需要增加：

- I2C 扫描和 `QMI8658A` 原始数据输出。
- `IO4` Logo 触摸原始值、基线和触摸状态输出。
- `MOTOR_FAULT / IO37` 原始电平和电机动作后的故障状态输出。
- 电机和喇叭工作时的触摸误触检查。

## 剧情层

剧情层负责把事件变成表现。

| 文件 | 职责 |
| --- | --- |
| `ScenarioEngine.*` | 根据事件和上下文选择计划 |
| `ScenarioExecutor.*` | 非阻塞执行计划 |
| `ScenarioLibrary.*` | 内置剧情规则 |
| `FacePack.*` | 表情帧 |
| `LightPack.*` | 灯光帧 |
| `MotionPack.*` | 动作帧 |
| `VoiceLinePack.*` | 台词表 |

剧情计划由四部分组成：

- 表情
- 灯光
- 动作
- 台词

## 提醒层

| 文件 | 职责 |
| --- | --- |
| `DeviceLocaleStore.*` | 保存设备语言，用于提示音、验证码播报和后续语音服务默认语言 |
| `LocaleResourceStore.*` | 只读取并校验当前语言资源分区，不负责下载、语言切换或播放 |
| `TimeService.*` | 提供当前时间 |
| `ReminderStore.*` | 保存提醒 |
| `ReminderManager.*` | 判断到期并生成事件 |

提醒层只产生事件，不直接控制硬件。

## 实时语音层

实时语音层负责本地语音链路和一次语音回合：让本地麦克风链路常驻运行，在明确唤醒后开始上传，等待服务端回放，记录失败状态。

| 文件 | 职责 |
| --- | --- |
| `LocalAudioPipeline.*` | 负责常驻本地采音，以及语音回合有效时的短上传队列 |
| `RealtimeVoiceService.*` | 管理普通回合和连续对话回合状态 |
| `RealtimeAudioSender.*` | 接收出站音频帧并记录发送统计 |

当前定版原则：本地音频链路常驻，唤醒词和 Logo 单击只负责开始上传，不负责打开麦克风。详细方案见 `docs/语音链路常驻方案.md`。

连续对话时序已经按小智的半双工思路对齐：铜豆回复播放队列彻底排空后，等待 `120 ms` 扬声器尾音保护时间，再自动以 `auto` 模式开始下一轮上传。固件不再用本地平均音量门控决定用户有没有继续说话，而是交给服务端人声检测。

正常在线退出也由服务端统一裁决。精确命令、语义退出、无人说话和设备手动请求都进入服务器同一个出口；服务器先发送告别音频，再发送明确的 `goodbye`。铜豆收到后锁住连续监听，等软件音频队列和扬声器硬件缓冲都排空，再回到空闲。只有网络断开、发送失败或服务器无响应时，固件才走本地异常兜底。

实时语音层不决定铜豆怎么演。失败时只产生失败事件，由 `App` 交给剧情层选择“被咖啡呛到”等补救剧情。

### 实时语音后端层

实时语音后端层负责接外部语音服务，但命名必须保持铜豆主体。

当前定版：

- 目录使用 `firmware/src/tongdou_voice/`。
- 模块使用 `TongDouVoice*` 命名。
- 当前兼容协议是 `xiaozhi_esp32_serve`。
- 不使用 `firmware/src/xiaozhi/` 作为固件目录。
- 不使用 `Xiaozhi*` 作为铜豆固件模块名。

`2026-08-24` 实机验收后的准备状态规则：

- N4R2 的 `2 MB` PSRAM 必须先识别成功。
- 编解码器初始化失败时，语音客户端直接进入失败状态，不建立语音长连接。
- 后端握手成功不能单独代表语音准备完成；还必须确认当前需要的 Opus 编码和解码能力可用。
- Opus 原生错误码和错误文字必须进入设备状态，不能只返回一句笼统的“语音失败”。
- 正常半双工语音回合仍同时保留编码器和解码器；实测无需搬迁现有音频缓冲区，也无需改成错峰生命周期。

详细设计见 `docs/铜豆实时语音后端架构.md`。

## 网页层

网页层负责配置，不负责剧情执行。

| 文件 | 职责 |
| --- | --- |
| `WebConfigServer.*` | HTTP 服务和路由，包括 WiFi、语言、时间、提醒和诊断入口 |
| `ScenarioConfigApi.*` | 剧情配置接口 |
| `ScenarioConfigStore.*` | 用户剧情配置存储 |

网页诊断接口只能调用诊断层，不允许直接控制硬件。

## MCP 层

MCP 层负责把铜豆能力暴露给电脑端大模型和实时语音服务器。

后续扩展能力优先走 MCP（模型上下文协议）事件入口。  
邮件、日程、吃药提醒、电脑任务完成提醒等外部能力，不应该直接塞进硬件层或剧情层。

边界是：

> MCP 和本地助手负责把外部世界整理成事件，铜豆内部模块负责决定怎么提醒、怎么显示、怎么演。

当前最小工具：

- `get_status`：获取联网、时间、硬件降级和保留能力。
- `create_reminder`：创建提醒。
- `list_reminders`：查询提醒。
- `delete_reminder`：删除提醒。
- `play_scenario`：按事件名触发剧情。
  - 彩蛋表演事件：`dance_show`（国内版）、`dance_show_global`（海外版）。
- `set_personality`：切换人格模式。
- `start_voice_turn`：开始一次实时语音回合。
- `voice_exit`：请求服务器按正常告别时序结束当前会话。
- `voice_status`：查看实时语音状态。
- `play_voice_response`：播放服务端返回文本。
- `fail_voice_turn`：报告语音回合失败并触发补救剧情。

MCP 层只处理协议和工具注册，不直接控制硬件。需要触发剧情或切换人格时，必须交给 `AppCommandService`。

### 实时语音提醒边界

实时语音连接不会公开完整 MCP 工具表，只公开以下白名单：

- `tongdou.reminder.create`
- `tongdou.reminder.list`
- `tongdou.reminder.delete`

网页 `/api/mcp` 仍保留完整工具表，供本地调试和受控的本地助手使用。这样做是为了防止大模型误调用语音后端配置、诊断或剧情管理工具。

语音提醒的职责边界：

```text
服务端：把自然语言整理成相对秒数或明确的本地日历时间
MCP：传递结构化调用和真实执行结果
TimeService：用设备已同步时钟换算并校验到期时间
ReminderStore：持久保存提醒
ReminderManager：本地判断到期并发出事件
剧情层：决定到点后怎么显示、播报和动作
```

提醒创建禁止要求大模型心算 Unix 时间戳：

- “五分钟后”传 `delaySeconds: 300`。
- “今天 19:10”传 `localDateTime: 2026-08-24 19:10:00`。
- `dueAt` 只接受外部已经从可信时钟得到的绝对时间。

`App` 只把实时语音传来的 MCP 请求接到 `McpServer`，不解析提醒内容，也不直接写提醒存储。

### 提醒播报与多语言资源边界

提醒到期后的正常路径使用服务端在线语音播报具体提醒正文；离线路径不尝试在固件内保存每条提醒的语音，也不把所有语言的异常播报一起打包进固件。

固件只维护一个当前语言资源槽。所有本地化欢迎语、配网、验证码、数字、升级、错误提示、`offline_notice.ogg` 和固定界面小字库组成一套语言资源包，其他语言版本全部由服务器保存。语音文件使用 Ogg 容器封装 Opus 音频，不再把多套语言文件嵌入应用程序镜像。

语言切换时，完整新资源包先下载到外部扩展内存，在内存中完成校验后再覆盖唯一持久资源槽，最后保存语言设置。外部扩展内存只负责下载和播放缓冲，不能承担断电后仍需存在的资源存储。单资源槽更新若遇到写入期间断电，启动校验负责发现损坏并重新下载；本项目不为保留新旧两份语言包设置双资源槽。

固定界面使用当前语言的小字库。任意提醒正文由服务器在创建提醒时预渲染为 128×48 单色图片，固件按提醒编号保存图片，避免下载中文、俄文等完整字库。

离线或在线语音失败时，执行顺序固定为：OLED 显示提醒正文、播放当前语言通用异常播报、等待喇叭排空、实时生成三声提示音。异常播报文件不可用时，直接退化为 OLED 正文和三声提示音。

### 当前语言资源分区（第一阶段已落地）

N4R2 的闪存末端固定预留一个 `0x20000`（128 KB）原始数据分区，分区名为 `locale`，地址范围为 `0x3D0000` 到 `0x3EFFFF`。它只保存当前语言的一套资源，不建立文件系统，避免和唤醒模型现有的文件系统分区混用。

资源包当前包含欢迎、配网、升级、激活码、激活错误、密码错误和数字 0～9 共 16 个 Ogg Opus 文件。包头保存格式版本、语言、资源版本、文件目录、总大小，以及“文件目录＋资源正文”的 SHA-256 摘要；固件启动时会检查边界、必需文件和摘要，任何一项不对就拒绝使用整个资源包。

生成命令：

```bash
cd firmware
python tools/build_locale_pack.py --locale ru-RU --output .pio/build/esp32s3/locale_ru-RU.bin
```

当前播放器会优先读取与设备当前语言一致的资源包，并把单个待播文件读入外部扩展内存后解码播放；资源包不存在、语言不匹配或文件损坏时，暂时回退到原来嵌入固件的语音，保证第一阶段可以单独验证和回滚。

本阶段还没有实现服务器下载、切换语言时覆盖旧包，也没有删除固件中原有的多语言文件。只有下载、校验、覆盖和异常兜底全部实机通过后，才能删除旧资源并真正回收闪存。

## 单一职责检查

新增文件前必须回答：

> 这个文件只负责什么？

如果答案里出现“同时、顺便、还负责”，就先拆。

## 禁止依赖方向

禁止：

```text
硬件层 -> 剧情层
硬件层 -> 网页层
硬件层 -> MCP 层
提醒层 -> 硬件层
网页层 -> 硬件层
```

允许：

```text
SystemBootstrap -> App
App -> 所有模块
剧情执行器 -> 硬件执行接口
提醒管理器 -> 时间服务 / 提醒存储
网页服务 -> 配置存储 / 提醒存储
MCP 服务 -> 提醒存储 / 时间服务 / 状态查询
MCP 服务 -> 应用命令服务
本地音频链路 -> 音频输入
实时语音服务 -> 本地音频链路 / 音频输出
```

## 提交前检查

改固件后至少检查：

- 是否破坏单一职责。
- 是否把剧情写进硬件层。
- 是否把硬件细节写进网页层。
- 是否能编译。

编译命令：

```bash
cd firmware
platformio run
```
