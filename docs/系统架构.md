# 系统架构

本文锁定当前固件架构边界。

## 一句话原则

铜豆固件按职责分层：硬件只管硬件，剧情只管表现，提醒只管时间，网页只管配置，`App` 只负责把它们接起来。

## 分层

```text
App
  -> Hardware
  -> Scenario
  -> Reminder
  -> Web
  -> MCP
```

## App 职责

`App` 只做三件事：

1. 初始化模块。
2. 每轮调用模块更新。
3. 把事件交给剧情层。

`App` 不允许直接写：

- 具体灯效。
- 具体电机动作。
- 具体台词。
- 存储格式细节。
- 电池百分比算法。
- 网页接口细节。

## 硬件层

硬件层只负责把真实硬件包成简单接口。

| 文件 | 职责 |
| --- | --- |
| `AudioInput.*` | INMP441 麦克风输入和音量诊断 |
| `AudioOutput.*` | 音频输出，后续接 NS4168 |
| `BatteryMonitor.*` | 电池、USB、充电、充满检测 |
| `DisplayBus.*` | I2C 初始化 |
| `FaceDisplay.*` | OLED 表情显示 |
| `LedPixel.*` | WS2812 控制 |
| `MotorDriver.*` | AT8833 双电机控制 |
| `RadarSensor.*` | 雷达信号读取 |

硬件层禁止知道剧情名。

## 剧情层

剧情层负责把事件变成表现。

| 文件 | 职责 |
| --- | --- |
| `ScenarioEngine.*` | 根据事件和上下文选择计划 |
| `ScenarioExecutor.*` | 非阻塞执行计划 |
| `ScenarioLibrary.*` | 内置剧情规则 |
| `FacePack.*` | 表情帧 |
| `LightPack.*` | 灯光帧 |
| `MotionPack.*` | 动作帧 |
| `VoiceLinePack.*` | 台词表 |

剧情计划由四部分组成：

- 表情
- 灯光
- 动作
- 台词

## 提醒层

| 文件 | 职责 |
| --- | --- |
| `TimeService.*` | 提供当前时间 |
| `ReminderStore.*` | 保存提醒 |
| `ReminderManager.*` | 判断到期并生成事件 |

提醒层只产生事件，不直接控制硬件。

## 网页层

网页层负责配置，不负责剧情执行。

| 文件 | 职责 |
| --- | --- |
| `WebConfigServer.*` | HTTP 服务和路由 |
| `ScenarioConfigApi.*` | 剧情配置接口 |
| `ScenarioConfigStore.*` | 用户剧情配置存储 |

## MCP 层

MCP 层负责把铜豆能力暴露给电脑端大模型。

当前最小工具：

- 获取状态
- 创建提醒
- 查询提醒
- 删除提醒

## 单一职责检查

新增文件前必须回答：

> 这个文件只负责什么？

如果答案里出现“同时、顺便、还负责”，就先拆。

## 禁止依赖方向

禁止：

```text
硬件层 -> 剧情层
硬件层 -> 网页层
硬件层 -> MCP 层
提醒层 -> 硬件层
网页层 -> 硬件层
```

允许：

```text
App -> 所有模块
剧情执行器 -> 硬件执行接口
提醒管理器 -> 时间服务 / 提醒存储
网页服务 -> 配置存储 / 提醒存储
MCP 服务 -> 提醒存储 / 时间服务 / 状态查询
```

## 提交前检查

改固件后至少检查：

- 是否破坏单一职责。
- 是否把剧情写进硬件层。
- 是否把硬件细节写进网页层。
- 是否能编译。

编译命令：

```bash
cd firmware
platformio run
```
