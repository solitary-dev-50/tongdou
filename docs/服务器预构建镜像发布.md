# 服务器预构建镜像发布（候选流程）

**状态：2026-10-01 已完成三个镜像的真实构建和 Windows Docker Desktop 隔离启动验收；尚未上传，也未在全新 Ubuntu 上验收。**旧 v0.1.2 压缩包是历史源码构建包，不要把它误当成新版轻量运行包。实测记录见 `release_validation/server_v013_rc1/验收结果.md`。

## 发布者做什么

当前候选版本为 `v0.1.3-rc.1`，源码仍使用已冻结的 v0.1.2 服务器源码包，避免混入开发目录里的未发布改动。最终远程名称为 `ghcr.io/solitary-dev-50/server`、`ghcr.io/solitary-dev-50/manager`、`ghcr.io/solitary-dev-50/voiceprint`，标签统一为 `v0.1.3-rc.1`。用户包的 `TONGDOU_IMAGE_NAMESPACE` 为 `ghcr.io/solitary-dev-50`。必须验证三个镜像均能匿名拉取后，才能分发候选运行包。

在铜豆仓库根目录执行：

```sh
python tools/build_server_release_images.py --source release_artifacts/TongDou_Server_v0.1.2_Early_Tester --version v0.1.3-rc.1 --namespace ghcr.io/solitary-dev-50 --vad-model /path/to/reviewed/silero_vad.onnx --asr-model-dir /path/to/reviewed/SenseVoiceSmall
python tools/package_server_runtime.py --source release_artifacts/TongDou_Server_v0.1.2_Early_Tester --version v0.1.3-rc.1 --namespace ghcr.io/solitary-dev-50 --output release_validation/server_v013_rc1/TongDou_Server_Runtime
```

脚本先构建并打好三个固定标签，全部构建成功才依次上传；若上传中途失败，修好仓库权限或网络后重试。只想本地检查时去掉 `--push`。**不要在镜像还未上传和实测前分发候选压缩包。**未来发布新版本时，换成对应的已审查源码目录和新版本号，不要混入当前开发目录的未发布改动。

冻结的 v0.1.2 源码包没有模型目录。`--vad-model` 必须指向经过核对的 Silero 人声检测模型文件，`--asr-model-dir` 指向完整的 SenseVoiceSmall 默认语音识别模型目录；构建脚本只把这些必需模型补入临时构建目录，不修改冻结源码。记录模型来源和文件摘要，下一次构建复用同一份已审查模型，不自动取最新模型。缺失模型时会在构建前停止，避免生成能构建却无法启动的镜像。模型已经包含在源码目录时可省略对应参数。

构建入口只在发布者机器运行。管理端 `Dockerfile-web` 已用多阶段构建，最终镜像没有 Node、Maven 构建环境；语音镜像用 `pip --no-cache-dir` 安装依赖；声纹镜像基于现有固定摘要基础镜像，并把启动程序复制进去。声纹模型继续首次下载到 `voiceprint-model-cache` 数据卷。

## 用户拿到什么

打包程序只复制运行文件、配置模板、启动/停止/查看状态脚本和声纹数据库初始化语句。新包不包含 Java、前端、Python 业务源码和 Dockerfile。三个服务在运行用 `docker-compose.yml` 中只有带同一 `TONGDOU_VERSION` 的 `image`，没有 `build`。用户先装 Docker，解压包，设置 `.env`，运行 `START_TONGDOU_SERVER.sh`（Linux）或 `.bat`（Windows）。启动入口先拉取，再启动和检查。

升级前备份 `.env`、`data/`、`uploadfile/` 和四个具名数据卷；新包沿用原 `COMPOSE_PROJECT_NAME`。启动程序不会删除卷。Linux 启动程序保留旧卷缺凭据的只读检查；Windows 启动程序发现相应旧卷而凭据缺失时也会拒绝自动生成。

## 正式发布前还要验收

1. 确认仓库前缀和账号确实有上传、下载权限，三个固定标签都能从全新机器拉取。
2. 在干净 Ubuntu 上做首次启动，记录三个最终镜像的实际下载大小、磁盘占用、内存峰值和五个服务健康状态；据实修订资源建议。1.6 GiB 内存、无交换空间的机器目前没有通过证明。
3. 用已有 v0.1.2 数据卷和原 `.env` 做升级，确认账户、配置、声纹数据与模型缓存都保留。
4. 单独验证旧卷存在而 `.env` 丢失会停下；再验证停止、重启、查看状态和声纹模型首次下载/再次复用。

2026-10-01 本地验收实际构建三个候选镜像，并用独立项目、端口和四个新卷启动五项服务。默认人声检测、语音识别模型缺失导致的启动阻断已在发布构建入口修复；运行包仍无本地构建步骤。未上传、未删除卷、未正式发布；旧归档和原有用户数据保持原样。
