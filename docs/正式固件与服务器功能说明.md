# 铜豆正式固件与服务器功能说明

## 一句话结论

铜豆当前已经形成一条可工作的完整主链路：设备负责本地唤醒、收音、播音、表情、灯光、电机、提醒和硬件安全，服务器负责语音识别、大模型回答、工具调用、语音合成、设备绑定、语言资源和固件升级信息。

这份文档只说明截至 `2026-09-07` 当前代码真正具备的能力，不把方案文档里的后续计划算成现成功能。

下文的“服务器”指铜豆配套的 `tongdou-server`。V9.4 另有连接 `xiaozhi.me` 的独立固件入口，当前只以配对和基础语音为目标，范围及验收状态见 [V9.4 小智云版固件](V9.4小智云版固件.md)。

## 1. 盘点范围

本次按以下两份实际代码盘点：

- 正式固件：`E:\ESP32-S3\Tong Dou\firmware`
- 铜豆服务器：`E:\ESP32-S3\tongdou-server`

功能状态分为三类：

| 状态 | 含义 |
| --- | --- |
| 已接通 | 固件和服务器已有对应代码，主流程能连起来 |
| 可配置 | 服务器已有能力，但需要在控制台启用、配置模型、填写密钥或部署配套服务 |
| 未闭环 | 有底层代码、测试入口或设计文档，但还不能当成完整产品功能宣传 |

当前正式固件和配套服务器测试包版本为 `0.1.2`。本次为早期测试发布：IP／控制台查询已由项目负责人确认实机通过；多人记忆和跨会话效果属于后续实测，不作为发布阻塞。不把量产级远程升级压力测试列为本次交付条件，也不宣称这些测试已经完成。

## 2. 两边怎么分工

可以把整套系统理解成：铜豆本体是身体，服务器是远端大脑。

| 能力 | 正式固件负责 | 服务器负责 |
| --- | --- | --- |
| 唤醒 | 麦克风常驻采音，在本地识别“你好，铜豆”，处理 Logo 触摸 | 接收唤醒文本，生成简短问候或进入正常回答 |
| 听用户说话 | 采集单声道语音，压缩后上传 | 判断人声、识别文字 |
| 思考和回答 | 接收回复并播放 | 调用大模型，组织回复文字 |
| 工具执行 | 真正创建提醒、读写音量、返回设备真实结果 | 判断何时调用工具，并把结构化参数发给设备 |
| 表情和动作 | OLED 表情、灯光、电机动作、安全降级 | 当前不直接控制具体电机速度、灯光颜色或屏幕像素 |
| 提醒 | 本地保存、判断到期、显示正文、完成后写入状态 | 创建前生成正文位图，到期时生成并合成播报 |
| 多语言 | 保存设备当前语言和唯一一套本地语言资源 | 保存各语言资源包并按需下发 |
| 配网和诊断 | 提供设备本地网页、状态接口和硬件自检 | 提供完整智控台，管理设备、角色、模型和插件 |
| 固件升级 | 判断安全时机，交给固定救援程序下载和安装 | 扫描版本文件，下发版本、大小、下载地址和摘要 |

## 3. 用户现在能直接使用的功能

### 3.1 第一次使用和联网

状态：已接通。

设备没有可用的已保存无线网络时，会进入本地配网模式。用户可以用手机或电脑打开铜豆本地网页：

配网热点开启后，屏幕会显示免密码热点的连接二维码；新填写的网络连接失败后也会重新进入配网模式。手机扫码识别率仍待实机验收，手动连接热点和输入 `192.168.4.1` 的方式继续保留。

固件最多保存 8 组无线网络及各自的服务器地址。开机先尝试附近已保存的网络，最近成功连接的一组优先；全部失败才打开配网热点。原来只保存一组网络的设备升级后会自动保留那组配置。多地点自动切换仍需实机验收。

用户从配网页保存新网络后，网页等待实际连接结果；只有连上目标无线网络并取得地址才显示连接成功和铜豆地址。成功后配网热点再保留约 60 秒供用户查看；失败时热点保持开放，网页提示检查密码、名称和信号并允许重试。连接结果不代表服务器或语音服务已就绪，手机热点切换期间的网页连续性仍需实机验收。

- 扫描附近无线网络。
- 填写无线网络名称和密码。
- 填写铜豆服务器地址。
- 保存并发起连接。
- 用手机或电脑当前时间给设备校时。

联网后，固件会向服务器注册设备并上报：

- 设备编号和网卡地址。
- 芯片型号、核心数、闪存大小和最低空闲内存。
- 固件名称和版本。
- 当前无线网络名称、信号、信道和设备地址。

服务器尚未绑定设备时，会返回激活码。铜豆会在 OLED 上显示激活码，并用当前语言资源播报激活码。绑定完成后，服务器返回语音长连接地址和令牌，固件自动连接语音服务。

### 3.2 本地唤醒和 Logo 触摸

状态：已接通。

正式固件的麦克风链路会常驻运行。这里的“常驻”是指麦克风一直在设备本地工作，不等唤醒后才临时打开；没有进入对话时，语音不会持续上传服务器。

当前交互入口：

| 入口 | 当前行为 |
| --- | --- |
| 说“你好，铜豆” | 设备本地识别成功后，通知服务器进入唤醒问候，并打开后续对话 |
| Logo 单击 | 先做轻微点头和表情反馈，再开始一轮语音对话 |
| Logo 双击 | 播放国内版小舞步剧情 |
| Logo 长按 | 请求服务器正常结束对话，并执行睡觉、熄灯、停电机表现 |

本地唤醒目前只有中文“你好，铜豆”。切换设备语言不会同时切换本地唤醒模型。

服务器能够忽略空格、标点和英文大小写差异，例如“你好 铜豆”和“你好，铜豆”会被当成同一个词。但部署时仍要在服务器或智控台的唤醒词配置里加入“你好铜豆”；仓库的单模块默认配置仍保留旧的小智唤醒词列表，直接照搬会失去铜豆专用快速问候判断。

### 3.3 实时语音对话

状态：已接通，但属于半双工。

“半双工”用大白话说，就是一边说完再轮到另一边说，不是双方同时抢话。

完整流程：

1. 本地唤醒或 Logo 单击打开收音上传。
2. 固件把麦克风声音压缩成 Opus 音频包。Opus 是适合网络传输的语音压缩格式。
3. 服务器做语音活动检测和语音识别。
4. 服务器把文字交给大模型。
5. 大模型可以直接回答，也可以调用服务器工具或设备工具。
6. 服务器把回答合成为语音并流式发回。
7. 固件边收边播放。
8. 播放队列和喇叭缓冲完全排空后，再等 `120` 毫秒尾音保护时间，自动进入下一轮收音。

当前已有这些保护：

- 外部扩展内存里有约 6 秒上行缓冲，降低网络偶发卡顿造成的丢音。
- 主循环每次只发送一个音频包，避免网络发送把屏幕、触摸和提醒全部堵住。
- 编码器或解码器没有准备好时，不会假装语音服务可用。
- 上行写坏或连接断开后，会结束本轮并回到可重试状态。
- 服务器长时间没有回复时，固件会结束本轮并触发失败表现。

当前不应宣传为“随时打断铜豆说话”。协议和调试接口已有中止播放能力，但正式自然对话仍按半双工工作，铜豆播音期间不会同时正常听用户讲话。

### 3.4 连续对话和正常退出

状态：已接通。

铜豆回答结束后会自动继续听，不需要每句话都重新喊唤醒词。

以下退出都由服务器走同一个正常出口：

- 用户说退出类语句。
- 连续对话中长时间没有人声。
- Logo 长按。
- 设备主动发送退出请求。

正常出口固定为：

1. 服务器先生成或选择一句告别语。
2. 告别语音发送完成。
3. 服务器发送明确的 `goodbye`，意思是“本次对话正式结束”。
4. 固件确认声音排空后回到空闲、睡觉眼并熄灯。

只有断网、发送失败或服务器无响应时，固件才走本地异常兜底，不伪装成正常告别。

### 3.5 语音状态的表情和灯光

普通表情页顶部左侧显示无线网络信号格和语音服务云朵，右侧只显示五格电池，取消电量数字。无线网络连接后显示 1～4 格，断开显示叉；云朵内勾表示设备语音连接已就绪，三点表示连接或握手中，叉表示当前不可用。连接就绪不保证远端模型或语音供应商每次调用都成功。电池每格约代表两成电量；未充电且电量不高于 10% 时最后一格亮一秒、灭一秒，外框常亮。充电时每充满两成电量就有一格常亮，下一格亮一秒、灭一秒，100% 五格常亮；电量计不可用时显示问号。准确百分比仍可通过语音和网页查询，具体边界见 [BQ27220 电量计接入](BQ27220电量计接入.md)。图标最多每秒检查刷新，除低电量和充电格跳动外，显示状态不变时不重复刷屏。激活码、提醒正文和网络地址等专用图片页面不叠加状态栏。

电脑端屏幕模拟测试已覆盖状态切换、电池不变时更新网络图标、电池刷新保留网络图标，以及专用页面不被覆盖；V9.4 实际屏幕显示仍待烧录验证。测试入口：`python firmware/tools/test_status_bar.py`。

状态：已接通。

| 语音状态 | OLED 表情 | 灯光 |
| --- | --- | --- |
| 正在听 | 倾听眼 | 低亮青色 |
| 正在思考、等待回复 | 认真眼 | 低亮蓝紫色 |
| 正在说话或结束 | 微笑 | 低亮暖色 |
| 回到空闲 | 睡觉眼 | 熄灭 |

提醒正文和失败补救剧情优先级更高，不会被普通语音表情抢走屏幕和灯光。

服务器虽然会发送旧的情绪字段，但当前固件只记录它，没有把服务器每句话的语义情绪映射成不同表情。因此“回答内容自动驱动得意、心虚、疑惑等表情”还没有闭环。

## 4. 大模型、人格和在线工具

### 4.1 大模型语音能力

状态：已接通，实际效果取决于服务器配置。

服务器把语音能力拆成多个可替换模块：

- 人声检测：判断什么时候开始说、什么时候说完。
- 语音识别：把声音转成文字。
- 大模型：理解问题、生成回答、决定是否调用工具。
- 语音合成：把回答文字变成声音。
- 意图和工具：执行天气、新闻、音乐、联网搜索和设备控制。
- 记忆：按配置选择无记忆、本地短期记忆、外部记忆或 PowerMem 记忆。

仓库支持多家本地或在线服务，但“代码支持”不等于“当前已经可用”。只有管理员完成模型选择、密钥、地址和费用配置后，对应能力才算可用。

### 4.2 铜豆统一人格

状态：服务器口吻策略已落地，三端同步未闭环。

服务器已有三种固定人格剧本：

- 温柔提醒：轻、暖、短，不抢戏。
- 嘴欠搭子：默认模式，先解决问题，再低频补一句嘴硬心软的反差。
- 彻底戏精：允许短小夸张，但不能更吵、更长或更冒犯。

服务器会给性格表达加冷却轮数，避免每句话都贫嘴；也会清理不适合语音的表情符号、波浪号和通用客服收尾，并检查工具失败时有没有谎称成功。

当前边界必须写清：

- 服务器的人格模式来自服务器配置，默认是嘴欠搭子。
- 固件的 `set_personality` 只修改当前运行内存中的剧情偏好，断电不会保存。
- 服务器尚未在 `hello` 握手消息中下发人格模式。
- 固件切换人格后，不会自动同步到服务器当前大模型提示词。
- 当前真正渲染的设备本地首页没有可靠提供端到端人格设置。

所以现在可以说“服务器已经按铜豆人格说话”，不能说“用户已经能在页面稳定切换三种人格，并在服务器、固件和重启后保持一致”。

### 4.3 服务器默认在线工具

状态：完整智控台中新建角色默认启用，部分工具仍需密钥或本地资源。

新建角色默认带四项工具：

- 播放服务器本地音乐目录中的音乐。
- 查询天气。
- 查询新闻。
- 联网搜索。

使用边界：

- 播放音乐要求服务器音乐目录里有可播放文件。
- 天气要求服务密钥和接口地址可用。
- 新闻依赖外部新闻聚合服务。
- 联网搜索要求配置秘塔或 Tavily 搜索密钥。

服务器还支持时间、家庭自动化、知识库、设备呼叫等插件，但它们没有全部作为铜豆默认能力启用，不能统一算进开箱即用功能。

### 4.4 服务器可选记忆和声纹

状态：可配置；后台保存和身份隔离已有实现与自动测试，多人实机仍待后续验证。

完整服务器支持：

- 保存对话历史和语音记录。
- 生成会话标题和总结。
- 无记忆、本地短期记忆、外部记忆和 PowerMem 多种记忆方式。
- 声纹识别，也就是根据声音判断正在说话的人。
- 在启用声纹和支持的记忆模块后，同一台铜豆可以按不同声纹档案隔离记忆，避免甲的私人记忆串给乙。

当前单模块配置模板已选择 PowerMem；完整智控台模式以角色的实际记忆配置为准，模板选择不等于密钥、声纹和模型已配置。

当前后台使用 PowerMem 1.1.7、用户画像和 SQLite 单库保存：会话结束先持久保存待处理任务，再由后台提取、更新记忆；失败保留任务并按原规则重试，不能把“收到任务”当成“记忆已保存”。数据库与任务队列需指向同一文件，默认 `data/powermem_dev.db`。

人物编号来自可信声纹档案，普通记忆同时按人物与设备过滤，画像按人物保存；未识别身份不读取或保存长期记忆。自然陈述的长期偏好可参与提取，最终是否保存由后台结果决定，不保证每句话都会记住。配套包不包含任何现有用户记忆、录音、声纹或服务密钥。

后台保存有自动测试和本地部署记录；跨会话回答效果及多人记忆仍待后续实测，不能描述为已完成所有真实用户场景验收。配置和验证步骤见 [v0.1.2 测试版交付说明](v0.1.2测试版交付说明.md)。

## 5. 设备工具能力

MCP 是“模型上下文协议”，大白话就是让大模型用统一格式调用设备真实能力。

### 5.1 实时语音允许调用的设备工具

状态：已接通。

实时语音连接只向服务器公开受限的正式工具。2026-09-23 增加四个短动作入口，代码已接通，实机语音验收待做：

| 工具 | 用户能做什么 |
| --- | --- |
| `tongdou.reminder.create` | 创建普通提醒，或创建带提前节点和正点节点的事件 |
| `tongdou.reminder.list` | 查询设备里真实存在的未完成提醒 |
| `tongdou.reminder.delete` | 删除提醒；事件提醒会一起删除同事件的未完成节点 |
| `tongdou.reminder.snooze` | 延后刚播报的提醒，不破坏同事件正点节点 |
| `tongdou.audio.get_volume` | 读取设备当前真实喇叭音量 |
| `tongdou.audio.set_volume` | 设置音量百分比、静音，或按增量调大调小 |
| `tongdou.network.show_info` | 自然询问本机地址或控制台入口时，读取真实地址并显示在屏幕上 |
| `tongdou.battery.get_status` | 读取真实电池状态；电量计不可用时不编造百分比 |
| `tongdou.motion.forward` | 前挪一下，自动停止 |
| `tongdou.motion.backward` | 后退一下，自动停止 |
| `tongdou.motion.wiggle` | 左右短扭一次，自动停止 |
| `tongdou.motion.stop` | 停止当前电机动作及回正，保留对话和提醒 |

动作不支持精确步数或距离，不允许用重复调用拼成长距离；成功响应只表示开始执行。提醒播报、安静模式、已知低电量和动作忙时拒绝新动作，停止不受这些限制。现有语音链路在播音期间不同时收音，因此不能宣传“随时喊停”。执行边界和验收步骤见 [语音动作控制](语音动作控制.md)。

网络查询沿用现有自然语言理解和语音回复，不要求固定口令。中文短确认示例：“我的地址已经显示在屏幕上了，照着找我就行。”地址页至少显示 30 秒，等待回复和播报时延长；自动进入下一轮监听不收起，服务端识别到用户下一句文本后立即收起，提醒优先。没有地址或屏幕不可用时如实返回失败。此能力已通过电脑端逻辑测试和固件编译，2026-09-07 项目负责人已确认 IP／控制台查询实机试用通过。完整实现与验证步骤见 [网络信息查询](网络信息查询.md)。

音量范围是 `0%` 到 `100%`，当前代码默认值是 `60%`。设置保存在芯片配置区，断电后仍然保留。音量只控制喇叭，不控制麦克风增益、唤醒灵敏度或服务器语音合成音量。

### 5.2 本地网页调试可调用的扩展工具

状态：已接通，但属于开发和诊断入口。

设备本地 `/api/mcp` 接口还可以调用：

- 查询设备状态。
- 创建、查询、删除和延后提醒。
- 触发审核过的剧情事件。
- 临时设置固件剧情人格。

## 6. 提醒系统

### 6.1 普通提醒

状态：已接通。

用户可以说：

- “五分钟后提醒我喝水。”
- “今天晚上七点十分提醒我关窗。”
- “十点开会，提前十分钟提醒我准备。”

服务器负责把自然语言整理成结构化时间，设备用自己已经同步的时钟校验并保存。大模型不需要自己心算时间戳。

设备最多保存 `12` 个提醒节点。普通提醒占一个节点；“提前提醒加正点提醒”的事件占两个节点；延后会再增加一个节点。这里的节点就像同一件事的几个闹钟，不等于十二件完整事件。

提醒正文在设备中最多保存 `95` 个字节。中文通常一个字占三个字节，所以可保存的中文字数会明显少于 95 个。

### 6.2 会议和事件提醒

状态：已接通。

会议类提醒可以把以下节点放在同一个事件编号下：

- 提前准备提醒。
- 用户延后提醒。
- 正点提醒。

延后只新增同事件节点，不会误删正点提醒。删除事件中的任意一个节点时，会一起取消这个事件所有尚未完成的节点。

### 6.3 提醒正文显示

状态：已接通。

服务器在创建提醒前，把正文排版成 `128×48` 单色图片，并随工具调用交给设备。设备把图片保存到独立闪存分区，到点后直接显示，不需要在 4 MB 闪存里塞完整中文、俄文或法文字库。

图片会按设备屏幕宽度自动换行和缩小字号。中文渲染要求服务器安装可用的思源黑体一类中文字库；缺字库或正文放不下时，服务器会明确拒绝创建，避免到点后显示乱码。

### 6.4 到点播报和离线兜底

状态：已接通。

在线流程：

1. 设备立即显示提醒正文图片。
2. 设备向服务器发送独立提醒播报请求，不伪装成用户说了一句话。
3. 服务器可以给正文加一句短而自然的前缀，但必须逐字保留完整正文。
4. 大模型输出不符合要求时，服务器直接使用固定安全前缀加原正文。
5. 服务器合成语音并发回设备。
6. 声音真正排空后，设备才把该提醒写成已完成。

离线或在线播报失败时：

1. OLED 继续显示正文图片。
2. 播放当前语言的通用离线提示。
3. 等喇叭排空。
4. 实时生成三声提示音。

如果本地语言资源损坏，仍保留 OLED 正文和三声提示音。

### 6.5 提醒后的回应窗口

状态：已接通。

在线提醒播完并提交完成状态后，设备会自动开放最长约 8 秒的收音，让用户直接说：

- “五分钟后再提醒我。”
- “把这件事取消。”
- 或继续说别的内容。

这个窗口会带上刚播报提醒的真实编号，因此用户不需要自己知道提醒编号。无人说话时，服务器结束本轮，设备安静回到空闲。

### 6.6 雷达驱动的主动提醒

状态：已接通。

正式固件用 LD2412 雷达的“有人/无人”结果维护桌前会话：

- 默认连续有人 `60` 分钟后提醒起来活动。
- 默认连续有人 `45` 分钟后提醒喝水。
- 用户离开超过 `5` 分钟后，重新计算桌前时长。
- 两种提醒都到期时会轮流播，不会一直偏向同一种。
- 不同类型提醒之间至少间隔 `5` 分钟，避免连续轰炸。

用户可以在设备本地网页分别开关两种主动提醒，并把周期设置为 `1` 到 `1440` 分钟。设置会断电保存。

服务器在线时会生成一句短而自然的铜豆式提醒；离线时只能使用通用离线提示和提示音。雷达只证明“检测到目标”，不证明用户姿势不对、缺水、在工作或一定是某个人，代码没有做这些越界判断。

## 7. 表情、灯光和电机动作

状态：已接通。

当前表情库已经包含睡觉、睁眼、眨眼、微笑、认真、翻白眼、困倦、委屈、眯眼、无辜、疑惑、生气、惊讶、害羞、凶、得意和紧张等表现。

当前灯效包括：

- 熄灯。
- 柔和白光。
- 暖色唤醒。
- 红色短闪。
- 暖色短闪。
- 弱呼吸。
- 低亮暖色。

当前动作包括：

- 停止。
- 点头和微点头。
- 轻晃。
- 向前轻顶。
- 前倾。
- 后缩。
- 小舞步。

电机动作执行器会读取 QMI8658A 陀螺仪数据，对转向动作做简单回正控制。电机故障脚 `IO37` 拉低时，驱动会拒绝继续动作，并把设备标成降级状态。

当前会自动触发的主要剧情：

- 开机安静唤醒。
- Logo 单击、双击和长按。
- 普通提醒、活动提醒、喝水提醒。
- 语音识别或网络语音失败的补救表现。

失败补救的电机动作改为原地轻微左右短扭，各约 20 毫秒，额外陀螺仪回正最多 20 毫秒；动作和回正均使用网页保存的左右轮正常力度，通过时间控制幅度。2026-09-26 用户反馈半力度低于电机启动门槛 160、实机不转，故取消半力度方案。正常力度仍为左右各 190；此版已完成 V9.4 编译并通过 USB 刷入，写入校验成功，实机幅度待观察验收。
- 连续对话超时后的睡觉表现。

低电量、开始充电、用户到来和用户离开等事件虽然已有剧情规则或事件编号，但还没有从硬件状态自动接入主循环，当前只能通过调试工具触发其中一部分。

## 11. 固件远程升级

状态：代码已接入，三个固件环境已编译成功；作为早期测试能力交付，未宣称完成量产级断网断电压力测试。

4 MB 闪存放不下两份完整正式固件，因此当前路线是“固定救援程序加一份正式固件”。

流程：

1. 正式固件定期向服务器上报当前版本。
2. 服务器扫描 `data/bin` 目录中的版本文件。
3. 有新版本时，服务器返回版本号、文件大小、下载地址和 SHA-256 摘要。
4. 固件只在接着 USB、电机和剧情已停止、语音与提醒空闲、喇叭排空时交接升级。
5. 设备重启进入固定救援程序。
6. 救援程序连接已保存的无线网络，下载并逐块写入正式固件分区。
7. 文件大小、摘要和芯片镜像格式全部正确后才启动新固件。
8. 新固件稳定运行 `10` 秒后确认成功。
9. 确认前崩溃或复位时，救援程序向服务器请求另一个版本，避免反复安装同一个坏版本。

当前安全边界：

- 只接受和设备注册接口同源的普通 HTTP 地址。
- 强制核对大小、摘要和镜像格式。
- 普通升级不覆盖无线网络、语言、提醒、音量和服务器地址。
- 第一次迁移到新分区布局必须用 USB 完整擦除并执行出厂烧录，旧布局不能远程迁移。

这套校验能防文件损坏和串错服务器，不能证明服务器身份。直接放到公网前，必须补带证书校验的加密连接或固件数字签名。

## v0.1.2 配套管理端的升级边界

当前 Python 单模块服务已有按版本、大小、摘要下发镜像的实现；完整智控台的设备注册和升级回复尚未完整对齐救援程序所需元数据，不能把这两种部署方式混为已接通。v0.1.2 配套服务器按完整智控台交付，默认采用 USB 烧录，不自动放入远程升级镜像。固件包保留 OTA 单应用文件供兼容环境后续使用，不宣称随包管理端远程升级已验收。本次不扩展修改升级业务。
