# JiShi 资产复用评估

本文用于判断 `可参考的项目/JiShi` 里哪些软件资产适合铜豆复用。

## 一句话结论

铜豆不是迁移到 JiShi，而是用 JiShi 已经跑通的软件体系，给铜豆 PCB 做板级适配。

## 可以优先复用

| JiShi 资产 | 铜豆价值 | 处理方式 |
| --- | --- | --- |
| 系统启动编排 | 启动、降级、配置模式 | 保留结构，换铜豆硬件 |
| 网页配置和诊断 | 配网、状态查看、剧情配置 | 页面内容改成铜豆 |
| MCP 工具层 | 接电脑端大模型 | 保留协议和工具注册结构 |
| 网络和时间服务 | 联网、校时、提醒可靠性 | 按铜豆需求裁剪 |
| OLED 表情状态层 | 表情显示基础 | 换铜豆眼神资源 |
| 音频播放结构 | 后续接 NS4168 | 换铜豆引脚和播放源 |
| 状态机组织方式 | 让设备像产品而不是实验 | 保留事件驱动思想 |

## 需要改造复用

| JiShi 资产 | 为什么要改 | 铜豆做法 |
| --- | --- | --- |
| 麦克风驱动 | JiShi 是更复杂的麦克风链路 | 改成 INMP441 单麦 |
| 运动系统 | JiShi 是舵机 | 改成双电机动作 |
| 主控制器 | JiShi 场景更复杂 | 只保留铜豆第一版需要的状态 |
| 本地解析框架 | JiShi 业务不同 | 改成提醒、安静、确认、失败补救等事件 |

## 不进入第一版

- 摄像头。
- 儿童教育业务。
- 儿童身份资料。
- 兴趣图谱。
- 成长记录。
- 多供应商复杂云端适配。

## 迁移顺序

1. 网页配置和诊断。
2. 系统启动编排。
3. 硬件 ready/degraded 状态。
4. 单麦音频输入。
5. NS4168 音频播放。
6. OLED 表情状态层。
7. MCP 工具层。

## 边界

铜豆第一版要先能演示、能提醒、能稳定工作。

JiShi 给的是成熟工具箱，不是让铜豆背上不属于它的业务包袱。
