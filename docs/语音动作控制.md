# 语音动作控制

2026-09-23：正式固件新增前进、后退、扭动、停止四个设备工具。V9.4 已编译；电脑模拟验证不代表实机语音验收。共用主线代码，因此 V9.0 也包含这些入口。

## 用户怎么说

先唤醒铜豆，等它听话时说“往前挪一下”“往后退一点”“扭一扭”或“停止移动”。服务器根据意思选择工具，不要求固定口令。

| 工具名 | 执行内容 |
| --- | --- |
| `tongdou.motion.forward` | 两轮前进 100 毫秒 |
| `tongdou.motion.backward` | 两轮后退 120 毫秒 |
| `tongdou.motion.wiggle` | 左右反向转动 70 毫秒，再反向 70 毫秒 |
| `tongdou.motion.stop` | 立即取消当前电机序列和回正，输出停止 |

前三项复用现有动作，开始前有约 180 毫秒陀螺仪静止采样；结束后必要时有最长 900 毫秒的朝向回正。以上时长由主循环推进，不能当成硬实时停机保证。实际位移受地面、电池和电机校准影响，不支持精确步数或厘米数。所有工具均无参数，不提供轮速、持续时长或循环次数；模型不得重复调用拼接长距离。

## 状态和优先级

- 提醒正在播报时拒绝新移动，已到期提醒仍按原流程接管动作。
- 安静模式或已知低电量时拒绝新移动。电量计不可用时不会编造电量百分比或低电量结论。
- 当前有动作时返回忙，不覆盖、不排队。
- 电机故障或陀螺仪未就绪时启动失败；执行中故障继续由现有动作控制器停止。
- 停止优先处理，即使低电量、提醒中或已经停止也接受。停止只管电机，不取消提醒、不结束对话、不清屏、不熄灯。
- 停止取消的是当前动作，后续新的用户请求或提醒仍可发起自己的动作。
- 没有新增避障、桌沿检测或倾倒识别能力。

语音工具结果中的 `ok=true, code=motion_started` 只表示接受并开始准备执行，不能声称已经走完；`motion_stopped` 表示当前序列已取消。失败返回 `ok=false` 和错误码：`reminder_active`、`quiet_mode`、`low_battery`、`motion_busy` 或 `motion_unavailable`。

语音仍是半双工，即一方说完另一方再说。铜豆播放语音期间不同时接收用户语音，服务器处理也需要时间，所以“停止移动”不是可随时使用的硬件急停。

## 协议与接线

语音和本地 `/api/mcp` 共用四个工具。服务器已有动态读取设备工具列表并转发的实现；升级固件后重新连接语音服务器，让服务器重新读取工具列表。没有修改服务器源码。

调用示例（将工具名换成另外三项即可）：

```json
{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"tongdou.motion.forward","arguments":{}}}
```

工具注册在 `McpServer.cpp`，应用命令层做请求状态检查，`ScenarioExecutor` 复用现有动作和唯一陀螺仪控制器。没有修改电机引脚、动作帧、力度或原有剧情。
