## 一句话结构

铜豆新版硬件由 `ESP32-S3` 直接负责采音、联网、播放、表情、灯光、电机和提醒。

主要模块：

- 主控：`ESP32-S3-MINI-1-N4R2`
- 麦克风：`IM72D128V01XTMA1`，PDM 数字麦克风
- 功放：`NS4168`，I2S 数字输入单声道 D 类功放
- 显示：0.96 寸 OLED，I2C 接口
- 灯光：`WS2812B-2020` 单颗彩色灯
- 电机驱动：`AT8833CT`
- 姿态传感器：`QMI8658A`，与 OLED 共用 I2C
- 触摸输入：铜豆 Logo 电容触摸，接 `IO4`
- 雷达：`LD2412` 接口
- 充电：`TP4057`
- 供电：电池、USB 5V、升压 5V、3.3V 稳压

## 主控引脚定义

| 主控引脚 | 网络名 | 用途 | 说明 |
| --- | --- | --- | --- |
| `EN` | `EN` | 主控复位使能 | 低电平复位 |
| `IO0` | `BOOT` | 下载模式 | 烧录时使用 |
| `IO1` | `PDM_CLK` | 麦克风 PDM 时钟 | 接 `IM72D128V01XTMA1 CLOCK` |
| `IO2` | `PDM_DATA` | 麦克风 PDM 数据输入 | 接 `IM72D128V01XTMA1 DATA` |
| `IO4` | `LOGO_TOUCH` | 铜豆 Logo 触摸输入 | V9 新增，先做原始值和误触验证 |
| `IO5` | `I2C_SDA` | I2C 数据线 | OLED 与 `QMI8658A` 共用，4.7k 上拉到 3.3V |
| `IO6` | `I2C_SCL` | I2C 时钟线 | OLED 与 `QMI8658A` 共用，4.7k 上拉到 3.3V |
| `IO7` | `LD2412_OUT` | 雷达有人输出 | 当前样机配置为有人高电平 |
| `IO8` | `VBAT_ADC` | 电池电压检测 | 分压后进主控 |
| `IO9` | `WS2812_2020` | 彩灯数据线 | 接 WS2812 输入 |
| `IO10` | `RADAR_TX_TO_MODULE_RX` | 主控发给雷达 | 接雷达模块 `RX` |
| `IO11` | `RADAR_RX_FROM_MODULE_TX` | 雷达发给主控 | 接雷达模块 `TX` |
| `IO12` | `SPK_LCK` | 功放 I2S 左右声道时钟 | 接 `NS4168 LRCLK` |
| `IO13` | `SPK_BCK` | 功放 I2S 位时钟 | 接 `NS4168 BCLK` |
| `IO14` | `SPK_DOUT` | 功放 I2S 数据输出 | 接 `NS4168 SDATA` |
| `IO15` | `SPK_CTRL` | 功放控制脚 | 接 `NS4168 CTRL`，固件启动时拉高 |
| `IO17` | `USB_CHG` | USB 5V 检测 | 分压后进主控 |
| `IO19` | `USB_D-` | USB 数据负线 | 接 Type-C |
| `IO20` | `USB_D+` | USB 数据正线 | 接 Type-C |
| `IO35` | `CHRG` | 充电中状态检测 | 接 `TP4057 CHRG#`，低有效 |
| `IO37` | `MOTOR_FAULT` | 电机驱动故障检测 | 接 `AT8833CT nFAULT`，低电平表示故障 |
| `IO38` | `AIN1` | 电机 A 路控制 | 接 `AT8833CT AIN1` |
| `IO39` | `AIN2` | 电机 A 路控制 | 接 `AT8833CT AIN2` |
| `IO40` | `BIN2` | 电机 B 路控制 | 接 `AT8833CT BIN2` |
| `IO41` | `BIN1` | 电机 B 路控制 | 接 `AT8833CT BIN1` |
| `IO42` | `MOTOR_SLEEP` | 电机驱动睡眠控制 | 接 `AT8833CT nSLEEP`，高电平唤醒 |
| `IO48` | `STBY` | 充满状态检测 | 接 `TP4057 STDBY#`，低有效 |

注意：

- `IO26` 在 `ESP32-S3-MINI-1-N4R2` 上和内部 PSRAM 相关，不作为普通引脚使用。
- `IO45/IO46` 是启动相关脚，不随便分配外设。
- `IO8` 当前用于电池电压检测，属于 ADC1 通道，优先用于联网状态下也要稳定读取的电压检测。
- `IO4` 当前用于 Logo 触摸输入，不再作为麦克风预留脚使用。
- `IO5/IO6` 是共享 I2C 总线，OLED 和 `QMI8658A` 只能共用同一个总线初始化入口，固件里不要重复初始化。
- 当前 PCB 没有单独预留 `RSET/EN` 触点，也不计划安装复位轻触按钮；日常复位通过电源开关断电重启完成。
- 固件中的引脚定义必须以本表为准。

## 麦克风电路

麦克风使用 `IM72D128V01XTMA1` PDM 数字麦克风。

| IM72D128V01XTMA1 引脚 | 连接 |
| --- | --- |
| `DATA` | `PDM_DATA / IO2` |
| `VDD` | 3.3V |
| `CLOCK` | `PDM_CLK / IO1` |
| `SELECT` | GND，固定声道 |
| `GND` | GND |

布局要求：

- `IM72D128V01XTMA1` 是底部进音，PCB 封装必须有声孔。
- 声孔不能被外壳、铜皮、阻焊或丝印挡住。
- 麦克风远离电机、功放、电感和升压芯片。
- `PDM_CLK / PDM_DATA` 建议保留测试点。

## 功放和喇叭

功放使用 `NS4168`，它是 I2S 数字输入单声道 D 类音频功率放大器。

| NS4168 引脚 | 连接 |
| --- | --- |
| `BCLK` | `SPK_BCK / IO13` |
| `LRCLK` | `SPK_LCK / IO12` |
| `SDATA` | `SPK_DOUT / IO14` |
| `CTRL` | `SPK_CTRL / IO15` |
| `VDD` | `+5V` |
| `GND` | GND |
| `VOP` | `SPK+` |
| `VON` | `SPK-` |

注意：

- 喇叭上的 `+`、`-` 标记用于保持相位一致，不是电源正负极。
- 铜豆只有一只喇叭时，两根线接反通常不会影响声音；仍建议按标记连接，便于后续检查。
- `SPK+` 和 `SPK-` 都是功放输出，任何一端都不能接到 GND。

当前决定：

- `NS4168` 暂时保持 `+5V` 供电。
- `CTRL` 由 `SPK_CTRL / IO15` 控制，固件启动时拉高，固定功放工作状态。
- 后续必须实测 3.3V I2S 信号驱动 5V 供电的 NS4168 是否稳定。

## OLED 显示

OLED 使用 I2C 接口。V9 开始，OLED 与 `QMI8658A` 共用 `IO5/IO6` 这条 I2C 总线。

| 接口 | 主控引脚 | 说明 |
| --- | --- | --- |
| `SDA` | `IO5` | 数据线 |
| `SCL` | `IO6` | 时钟线 |
| `VCC` | 3.3V | 电源 |
| `GND` | GND | 地 |

注意：

- OLED 地址以实物扫描结果为准；目前板测固件已按 `0x3C` 验证点亮。
- `QMI8658A` 加入后，必须先做 I2C 扫描，确认 OLED 和 `QMI8658A` 都能被看到。
- 固件应由统一的 I2C 总线模块初始化 `Wire`，显示和姿态传感器不要各自重复初始化。

## QMI8658A 姿态传感器

V9 新增 `QMI8658A` 六轴惯性传感器，用于后续识别拿起、倾斜、轻敲、摇晃和倾倒等动作。

| QMI8658A 接口 | 主控引脚 | 说明 |
| --- | --- | --- |
| `SDA` | `IO5` | 与 OLED 共用 I2C 数据线 |
| `SCL` | `IO6` | 与 OLED 共用 I2C 时钟线 |
| `VCC` | 3.3V | 电源 |
| `GND` | GND | 地 |

回板验证要求：

- 先做 I2C 扫描，确认 OLED 和 `QMI8658A` 同时在线。
- 再读 `QMI8658A` 芯片身份和原始加速度、角速度数据。
- 第一版先用低频读取，例如 25Hz 或 50Hz，避免影响 OLED 刷新。
- 先只做诊断，不直接触发剧情。
- 如果后续接入倾倒检测，倾倒事件必须优先停止电机。

V9 实测结论：

- `QMI8658A` 已能在 V9 裸板和组装后样机上被固件识别。
- 实测 I2C 地址为 `0x6A`，芯片身份寄存器读数为 `0x05`。
- 铜豆整机水平放置时，偏航主要仍在 `Z` 轴；PCB 顶层朝下只会影响轴符号，不应简单改成 `X/Y` 轴。
- 板测固件 `/motor` 页已用 `QMI8658A` 做空载直行测试：先静止采样零偏，再从左右同速起步，用 `Z` 轴角速度和累积偏航小步修正左右轮输出。
- 当前 `/motor` 直行测试收尾使用软停，不再使用主动急刹，避免两侧轮子停止手感不一致。
- 该结论只代表板级和板测固件诊断通过，不等同于正式固件已经完成姿态互动。

注意：

- `QMI8658A` 的 I2C 地址以实物扫描为准，不在文档里写死。
- 如果 PCB 上 OLED 和 `QMI8658A` 都带上拉，要检查并联后的总线上拉是否过强。

## Logo 触摸输入

V9 新增铜豆 Logo 触摸输入，接 `LOGO_TOUCH / IO4`。

用途：

- 短触：后续可作为轻互动或确认输入。
- 双击：可作为明确的主动交互，不建议和单击含义混在一起。
- 长触：后续可作为休眠、唤醒、“还咖啡债”等人格彩蛋触发。
- 板测固件里可以先做简单验证，正式接入真实业务前必须完成误触测试。

当前实测结论：

- V9 样机已验证 `LOGO_TOUCH / IO4` 可用。
- 板测固件中，单击 Logo 触发眨眼。
- 双击 Logo 触发左右扭动，并使用 `QMI8658A` 的 `Z` 轴偏航数据做回正。
- 长按 Logo 可在休眠和唤醒之间切换。

回板验证要求：

- 串口打印 `IO4` 触摸原始值和触摸状态。
- 分别测试 USB 供电、电池供电、电机动作、喇叭播放、灯光变化时是否误触。
- 触摸阈值不要写死，建议后续做开机基线校准。
- 剧情播放中，Logo 触摸默认应先作为停止或确认，不要叠加触发新剧情。

| --- | --- |
| `VDD` | 3.3V |

## 电机驱动

电机驱动使用 `AT8833CT`。

| 主控网络 | 连接 |
| --- | --- |
| `AIN1 / IO38` | A 路输入 1 |
| `AIN2 / IO39` | A 路输入 2 |
| `BIN2 / IO40` | B 路输入 2 |
| `BIN1 / IO41` | B 路输入 1 |
| `MOTOR_SLEEP / IO42` | `nSLEEP`，高电平唤醒电机驱动 |
| `MOTOR_FAULT / IO37` | `nFAULT`，低电平表示电机驱动故障 |

| 驱动输出 | 接口 |
| --- | --- |
| `AOUT1` | 外接电机接口 |
| `AOUT2` | 外接电机接口 |
| `BOUT2` | 外接电机接口 |
| `BOUT1` | 外接电机接口 |

当前决定：

- `nSLEEP` 由 `MOTOR_SLEEP / IO42` 控制，并通过 100k 下拉到 GND，电机驱动默认休眠。
- 固件初始化时保持 `MOTOR_SLEEP` 低电平；执行电机动作前拉高唤醒，停止后拉低休眠。
- `nFAULT` 通过 10k 上拉到 3.3V，并接到 `MOTOR_FAULT / IO37`；低电平表示过流、过热、欠压或输出异常等电机驱动故障。
- 第一版靠固件限制动作时长，避免长时间堵转。

## 毫米波雷达接口

雷达使用 `LD2412`，接口按 6 针处理：

| 接口脚位 | 网络 | 主控引脚 |
| --- | --- | --- |
| 1 | `LD2412_OUT` | `IO7` |
| 2 | `RADAR_TX_TO_MODULE_RX` | `IO10` |
| 3 | `RADAR_RX_FROM_MODULE_TX` | `IO11` |
| 4 | `3V3` | 供电 |
| 5 | `GND` | 地 |
| 6 | `G` | 地 |

注意：

- `RADAR_TX_TO_MODULE_RX` 接雷达模块 `RX`，也就是主控发数据给雷达。
- `RADAR_RX_FROM_MODULE_TX` 接雷达模块 `TX`，也就是雷达发数据给主控。
- 当前样机雷达参数固定为：分辨率 `0.2m`，探测距离 `0.2m-2.6m`，无人持续时间 `5s`，光敏联动关闭。
- 当前样机 `LD2412_OUT` 配置为有人高电平、无人低电平；`IO7` 仅用于检查接线和模块自身输出，不能作为雷达调试精度的判断依据。
- 板测页面的“有人/没人”只认雷达串口上报的目标状态：目标状态为 0 表示没人，非 0 表示有人。距离门能量只用于诊断，不再由主控自行补判，避免制造与雷达模块结论不一致的假目标。
- 雷达装入整机并固定最终朝向后，应保持检测区域无人并执行一次动态背景校正。校正后不能通过转动雷达来切换空场和人体场景，而应保持雷达不动，让测试人员走入、走出固定检测区域。
- 背景校正完成后等待约 10 秒，再分别执行空场采样和 30～100cm 人体移动采样。当前正常模块 `HLK-LD2412_6C67` 实测：空场 25 帧全部无目标，人体移动 25 帧中 23 帧为运动与静止组合目标，两轮采样坏帧均为 0。
- 调参和校正时不要同时使用海凌科蓝牙应用与主控串口命令，避免两个控制端同时操作模块。
- `LD2412` 模块供电以实际模块输入标注为准；独立 USB-TTL 调试时，已验证该小模块使用 `5V` 供电更稳定。不要同时接 5V 和 3.3V。
- 实物回来后必须确认串口方向、输出电平、蓝牙配置和检测距离参数。

## 充电和电量检测

充电芯片为 `TP4057`。

| TP4057 引脚 | 网络 | 说明 |
| --- | --- | --- |
| `VCC` | `USB_5V` | USB 输入 |
| `BAT` | `VBATT` | 电池端 |
| `GND` | GND | 地 |
| `PROG` | `PROG` | 充电电流设置 |
| `CHRG#` | `CHRG` | 充电中，低有效 |
| `STDBY#` | `STBY` | 充满，低有效 |

状态检测：

- `CHRG` 通过 10k 上拉到 3.3V，并接 `IO35`。
- `STBY` 通过 10k 上拉到 3.3V，并接 `IO48`。
- 固件读取时要按低有效处理。

电量检测：

- `VBAT_ADC / IO8` 通过 100k/100k 分压检测电池电压。
- `USB_CHG` 通过 100k/150k 分压检测 USB 5V。

## 外接模块与导线

- OLED、LD2412 雷达、电机和喇叭均直接焊线到 PCB 焊盘，不安装排针或其他外接插座。
- 电池是唯一通过板载连接器接入的外部部件，使用 `H6` 电池线对板连接器；型号为 `HX-PH2.0-2PZZ`。
- 其他外接模块之间的短距离连接，准备约 100 mm、直径 0.5 mm 的裸铜线即可。
- LD2412 雷达必须使用带绝缘皮的铜线连接 `3V3`、`GND`、`OUT`、`TX`、`RX` 五根线。不要使用裸铜线，否则导线可能碰到接地的黄铜骨架而短路。
- 雷达带皮导线可沿轮子遮挡区域走线，但仍需确认没有被轮子挤压、磨破或拉扯。

## 供电链路

主要电源：

- `VBATT`：锂电池电压。
- `VBAT_5V`：电池升压后的 5V。
- `USB_5V`：Type-C 输入 5V。
- `+5V`：自动切换和开关后的系统 5V。
- `3V3`：由 `+5V` 经 LDO 转换得到。

当前结构：

```text
电池 -> 升压 -> VBAT_5V
USB  -> USB_5V
VBAT_5V / USB_5V -> 自动切换 -> 开关 -> +5V -> 3V3
```

注意：

- `NS4168`、电机驱动、3.3V LDO 都接在开关后的 `+5V`。
- `AP2112` 从 5V 降到 3.3V，实物回来后要测 WiFi 工作时温升。
- 电机和功放都是噪声源，布局时要让麦克风远离它们。

## 打样前检查清单

- `IM72D128V01XTMA1` 封装声孔方向正确。
- `IM72D128V01XTMA1` 远离电机、功放和升压电感。
- `NS4168` 封装脚位和喇叭正负确认。
- `NS4168` 5V 供电时，3.3V I2S 信号需要实测确认。
- `TP4057 CHRG/STBY` 是低有效，不能按高有效写固件。
- `USB-C CC1/CC2` 下拉电阻正确。
- `ESP32-S3` 启动脚没有被外部电路拉错。
- 所有外接座脚序和丝印方向一致。
