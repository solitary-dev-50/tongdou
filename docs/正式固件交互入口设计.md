# 正式固件交互入口设计

## 1. 一句话结论

正式固件的交互入口定为：

```text
本地音频链路常驻
  -> 唤醒词或 Logo 触摸开始上传并进入对话
  -> 一次唤醒打开一个对话窗口
  -> 窗口内不用反复叫铜豆
```

铜豆不能靠网页按钮对话。网页按钮只保留为开发调试入口。

语音链路实现细节以 `docs/语音链路常驻方案.md` 为准。这里重点说明用户交互入口和体验规则。

## 2. 铜豆是谁

铜豆不是安分守己的桌面助手。

铜豆是一个调皮、捣蛋、财迷、嘴上有点凶、动作又有点怂的桌面小搭子。

它要能帮用户记事、提醒、确认任务，但不能说成普通客服腔。

不应该说：

> 记下了，明天下午 3 点的会，我提前提醒你。

更像铜豆的说法：

> 行，明天下午 3 点的会。本豆提前薅你一下，账先记着。

或者：

> 收到，明天下午 3 点。我提前拽你，别装没听见。

众筹第一站面向西方用户时，也要保留这种调皮和轻微反叛感。英文表达不能变成老实助手，要像一个会讨价还价的小桌面角色。

## 3. 四种入口

### 3.1 雷达

雷达只负责判断：

> 附近大概有没有人。

雷达检测到有人时，铜豆可以醒来、亮屏、待命，做久坐提醒，或者调整睡觉眼和低功耗表现。

雷达不能直接开始录音上传。

雷达也不能作为麦克风、本地音频处理和本地唤醒检测的开关。

原因：

- 用户坐在桌前不一定是在叫铜豆。
- 用户也可能在铜豆背后。
- 雷达可能误判。
- 直接上传会有隐私压力。
- 直接上传会浪费服务器资源。
- 铜豆会变成烦人的监听设备。

### 3.2 唤醒词

唤醒词是正式语音入口。

第一版目标体验：

```text
用户：铜豆，明天下午 3 点有会，提前提醒我。
铜豆：行，明天下午 3 点的会。本豆提前薅你一下，账先记着。
```

这里必须支持“一句话唤醒并执行任务”。

不能强制用户这样说：

```text
用户：铜豆。
铜豆：我在。
用户：明天下午 3 点有会，提前提醒我。
```

这种两步流程只能作为兜底，不是默认体验。

### 3.3 Logo 触摸

Logo 是本体备用入口。

暂定规则：

- 单击 Logo：进入对话窗口，铜豆准备听用户接下来的话。
- 双击 Logo：短小彩蛋或小舞步，不进入主语音入口。
- 长按 Logo：关闭对话窗口，进入安静或收敛状态。

Logo 单击适合下面这种情况：

```text
用户摸一下 Logo
铜豆：嗯？本豆上线，快说，别浪费我待机电。
用户：明天下午我有会，下午 3 点，记得提前提醒我。
```

### 3.4 网页按钮

网页里的 `Start Voice Turn` 只作为调试入口。

它可以用来验证：

- 麦克风采音。
- 服务端连接。
- 语音识别。
- 大模型回复。
- 语音合成。
- 铜豆播放。

但不能作为正式用户交互方式。

## 4. 对话窗口期

一次唤醒后，必须打开一个对话窗口。

窗口期内，用户不需要每句话都叫“铜豆”。

当前实现不是先在固件里用平均音量猜“是不是人声”。铜豆每次回复播放队列彻底排空后，等待 `120 ms`，就自动进入一轮临时上传；服务端负责判断用户有没有继续说话。待机状态仍然不上传环境声音。

比如：

```text
用户：铜豆，帮我记个事。
铜豆：说吧，本豆收费但靠谱。
用户：明天下午我有会，下午 3 点，记得提前提醒我。
铜豆：行，明天下午 3 点。我提前拽你，别装没听见。
```

第二句没有再叫“铜豆”，铜豆也应该继续理解为用户在跟它说话。

## 5. 窗口计时规则

窗口期不应该太短。

10 到 15 秒偏急，像在催用户投币。

目标体验建议：

| 场景 | 窗口时间 |
| --- | --- |
| 刚被唤醒 | 30 秒 |
| 铜豆普通回答说完后 | 重新计时 30 秒 |
| 铜豆追问说完后 | 重新计时 45 秒 |
| 安静模式下 | 10 秒 |
| 雷达无人持续 | 收敛屏幕、灯光和动作表现，不作为唯一强制退出条件 |

最重要的规则：

> 窗口期从铜豆最后一次说完话开始重新计时。

当前已验证实现采用服务器裁决时序：

```text
回复播放队列排空
  -> 等待 120 ms
  -> 持续采音并上传
  -> 服务端有人声就进入下一轮回复
  -> 无人声达到服务器时限后生成告别语
  -> 服务端发送 goodbye
  -> 铜豆等喇叭尾音排空后退出窗口
```

`30 s / 45 s` 分级窗口仍是体验目标，目前尚未实现，不能把它写成当前服务器参数事实。

原因很简单：

- 用户可能要看日历。
- 用户可能要想时间。
- 用户可能要改口。
- 铜豆追问后，用户需要时间补充信息。

## 6. 退出窗口规则

退出对话窗口时，铜豆必须给用户明确反馈。

不然用户不知道铜豆到底还在不在听。

### 6.1 用户主动退出

用户说：

- 没事了。
- 算了。
- 退下吧。
- 先这样。
- 闭嘴。

目标行为是请求服务器正常退出，并播一句很短的退出语。不是设备自己悄悄关掉，也不是固件根据关键词硬猜。

当前机制已经落地：精确命令、明确的语义退出、保持安静和 Logo 长按等手动请求都进入服务器同一个退出出口。服务器先生成并发送告别语，再发送明确的 `goodbye`；铜豆收到后禁止再次开启连续监听，等喇叭尾音真正播完再回到空闲。网络故障时才使用本地失败反馈。

示例：

- 行，本豆退下。账先记着。
- 撤了撤了，别太想我。
- 收到，耳朵收起来了。
- 好嘞，我先装死。

### 6.2 窗口超时退出

无人说话达到服务器配置的时限后，也要由服务器播一句退出语，再发送 `goodbye` 并关闭本次会话。固件不能用本地计时抢先收口。

示例：

- 那我先不偷听了，叫我再说。
- 没动静？行，本豆省点电。
- 本豆先下线摸鱼，喊我再干活。
- 我先闭麦了，别说我偷听啊。

### 6.3 雷达无人

雷达无人不再作为语音窗口的唯一强制退出条件。

原因是用户可能在铜豆背后，雷达也可能短暂误判。

雷达无人时，可以收敛表现：

- 屏幕切到睡觉眼。
- 灯光降低。
- 动作减少。
- 长时间无人后进入更省电的陪伴状态。

但只要用户用唤醒词或 Logo 明确触发，铜豆仍然应该能回应。

### 6.4 长按 Logo 退出

长按 Logo 时：

```text
播一句短安静回复
  -> 关闭对话窗口
  -> 进入安静或收敛状态
```

示例：

- 行，本豆闭麦。
- 好好好，我安静点。
- 收到，进入省电装死模式。

## 7. 状态设计

第一版可以先按这些产品状态理解：

```text
无人睡觉
有人待命
对话窗口
正在听
正在想
正在说
安静模式
```

状态流转：

```text
雷达无人
  -> 无人睡觉

雷达有人
  -> 有人待命

本地音频链路常驻 + 唤醒词
  -> 对话窗口
  -> 正在听

本地音频链路常驻 + Logo 单击
  -> 对话窗口
  -> 正在听

正在听
  -> 正在想
  -> 正在说
  -> 对话窗口

对话窗口超时
  -> 播退出语
  -> 有人待命

用户主动退出
  -> 播退出语
  -> 有人待命

雷达长时间无人
  -> 无人睡觉或低功耗陪伴

长按 Logo
  -> 安静模式
```

当前基础视觉反馈已经落地：

| 语音状态 | 屏幕 | 灯光 | 结束条件 |
| --- | --- | --- | --- |
| 正在听 | 倾听眼 | 低亮青色 | 服务端开始回复或本轮停止上传 |
| 正在想 | 认真眼 | 低亮蓝紫色 | 收到第一段回复音频 |
| 正在说 | 开心眼 | 低亮暖白色 | 软件播放队列和喇叭缓冲排空 |
| 正常退出完成 | 睡觉眼 | 熄灯 | 收到服务器 `goodbye` 且最后一段告别语真正播完 |
| 异常失败 | 现有失败补救表情 | 暖色短闪 | 失败剧情完成 |

连续对话轮次之间存在约 `120 ms` 的播放尾音保护时间。视觉层额外保留 `250 ms` 的空闲确认时间，因此不会在“正在说”和下一轮“正在听”之间闪一下睡觉眼。这个确认时间只影响表情和灯光，不延迟采音、上传或服务器响应。

提醒正文、充电、低电量和故障的优先级高于语音状态。当前已实现提醒正文和语音失败避让；充电、低电量和故障的统一视觉优先级仲裁仍由后续基础状态管理补齐，不能在本文中写成已经全部完成。

## 8. 和小智方案的关系

小智固件的思路可以借鉴：

- 有待机、连接、监听、说话这些状态。
- 唤醒后进入监听。
- 自动模式下，服务端说完后可以回到监听，形成连续对话。
- 正在说话时再次唤醒可以打断。

铜豆不能照搬：

- 铜豆多了雷达存在感知。
- 铜豆有 Logo 本体交互。
- 铜豆有调皮、捣蛋、财迷的人格表达。
- 铜豆不能只像普通语音助手一样说话。

铜豆第一版可以借小智的“本地音频链路常驻、明确触发后上传”思路，再加上铜豆自己的对话窗口和人格表达。

雷达只作为桌前状态参考，不作为语音唤醒门控。

## 9. 第一版落地顺序

1. 保留网页按钮作为调试入口。
2. 雷达稳定输出有人和无人。
3. 本地音频链路常驻，不上传普通环境声音。
4. Logo 单击进入对话窗口，作为临时明确入口。
5. 对话窗口内不用重复叫铜豆。
6. 回复播放排空后等待 `120 ms`，自动进入临时上传，由服务端做人声检测。
7. 当前固定窗口无人说话时正常退出，不得播放语音识别失败提示。
8. 后续接本地唤醒词，支持“铜豆 + 任务”一句话执行。
9. 唤醒词稳定后，Logo 单击保留为备用入口。

## 10. 禁止事项

- 不允许雷达一检测到人就上传语音。
- 不允许强制每句话都叫“铜豆”。
- 不允许把网页按钮当正式入口。
- 不允许用客服腔确认任务。
- 不允许为了性格表演影响提醒可靠性。
- 不允许在安静模式里频繁播报。
- 不允许在用户离开后还大声说话。
