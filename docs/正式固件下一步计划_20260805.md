# 正式固件下一步计划 20260805

正式固件已经进入“主链路可跑通后的稳定化阶段”：不要再围绕日常固定台词扩展，下一步唯一核心是把实时语音、配置、表达和恢复能力做稳。

## 2. 当前已确认事实

- 正式固件目录是 `firmware/`。
- 正式固件已单独提交：`34efbe4 feat(firmware): connect formal voice firmware baseline`。
- 本地服务端已迁移到 `E:\ESP32-S3\tongdou-server`。
- 服务端仓库本地已有初始提交：`f5ef663 chore: import tongdou server baseline`。
- 铜豆实机已经跑通：麦克风采音 -> WebSocket 上传 -> 讯飞识别 -> 大模型回复 -> 讯飞合成 -> 铜豆播放。
- 固定台词只保留首次开机“恶魔诞生”登场，不作为日常交互主线。

## 3. 最高优先级

先做实时语音稳定性验收。

验收目标不是“能响一次”，而是连续多轮都能稳定完成：

```text
Start Voice Turn
  -> 用户说话
  -> 服务器识别出文字
  -> 大模型收到文字
  -> TTS 生成语音
  -> 铜豆播放
  -> 回到可再次对话状态
```

## 4. 第一阶段：语音链路稳定化

1. 连续测试 20 轮短句。
2. 记录每轮是否识别成功、是否回复、是否播放。
3. 记录失败时服务器日志和串口日志。
4. 检查连续对话后是否出现连接超时、播放卡死、状态不回到空闲。
5. 检查用户打断时是否能停止播放并重新开始听。

## 5. 第二阶段：配置闭环

1. 固件默认服务器地址继续使用 `ServerConfig.h`。
2. 网页配置能修改服务器地址、端口和路径。
3. OTA 返回的 WebSocket 地址和 token 能正确覆盖本地配置。
4. 设备绑定后不需要人工再输入验证码。
5. 断电重启后配置仍然生效。

## 6. 第三阶段：表达接入

1. 识别中显示“正在听”。
2. 等回复时显示“正在想”。
3. 播放时显示“正在说”。
4. 出错时显示明确失败表情。
5. 根据语音状态驱动灯光和轻微动作，但不能影响提醒可靠性。

## 7. 第四阶段：长期测试

1. 连续上电运行 2 小时。
2. 多次断网、恢复网络。
3. 多次重启服务端。
4. 多次重启铜豆。
5. 检查内存、连接、播放和状态是否恢复正常。

## 8. 当前不要做的事

- 不扩展日常台词包。
- 不把小智命名写进铜豆固件模块名。
- 不在正式固件里硬编码真实 API Key。
- 不把服务器数据库、上传文件、运行数据提交进仓库。
- 不急着做摄像头、复杂 MCP、完整智能家居。
